# 需求论证与研究记录

Last updated: 2026-10-01

当前需求主入口为[需求分析 v1.0](requirements-handoff.md)，编号与采用状态见[需求基线](requirements.md)。本文件保留完整推理、证据限制、H1–H6/V1–V5定义及历史研究经过，供按问题追查；其中按日期记述的范围建议与下一步不是当前执行清单。现行工作顺序见[里程碑](milestones.md)。

八部分主体已整理为v1.0。当前已确认多主题接续、实际外部发现和比赛demo优先；历史“记录待定”“维护先行”等表述仅为研究过程。真实用户收益与持续供给仍未验证，不能由文档定版推断通过。

## 1. 问题背景

### 背景基线与确定程度（2026-09-25）

**采用的背景表述：**高校及外部机构已经提供大量机会与支持，信息分布在学校、院系、课题组、研究所和其他平台。学生从自己的兴趣、参与目的及条件出发，可能仍需跨来源发现选项、理解实际任务与参与要求，并结合不同信息判断是否适合自己。产品研究这一选择过程中的困难，以及现有工具组合是否已经足够。

| 判断层次 | 当前结论 | 后续如何处理 |
| --- | --- | --- |
| 已有事实基础 | 官方网站、项目通知、资源入口与RSTAR等聚合服务已经存在；来源、对象和用途不同 | 使用下文已有来源支撑，不再以“学校没有平台”作为立项前提 |
| 已确定的研究问题 | 研究学生如何发现、理解、比较并自主选择机会与资源；介绍之外的实际参与情况也是比较内容 | 是产品研究范围，不因某个新案例而重写整个背景 |
| 仍待验证的原因与程度 | 分散是否造成漏看、现有说明哪里难懂、实际经历能否获得、哪些任务反复需要整理 | 按第8节H1—H6检验，不把“可能困难”写成所有学生的共同经历 |
| 尚未成立的收益主张 | 新产品比原站、搜索＋AI＋笔记更有用、更省时且能持续维护 | 需要同任务对照和供给验证；允许缩成导航、复用原服务或撤回候选功能 |

背景已经可以作为需求分析的稳定起点；尚未完成的是需求强度与产品必要性的实证判断。官方性质可能影响平台承载经历评价的方式只是待查假设，不能从中推出RSTAR没有反馈机制，也不能替代对具体经历供给的调研。


学生面对的不只是“在哪里找信息”，还包括判断机会是否适合、理解需要什么能力、取得行动资源，以及过一段时间后继续推进。学校和外部平台已经提供大量服务，研究的起点应是这些服务之间的任务如何衔接，而非预设“中科大缺一个平台”。

| 已有案例或数据 | 能支持什么 | 不能推出什么 |
| --- | --- | --- |
| 中科大软件学院 2026 年 9 月就业提醒自述已收集筛选 20 余家单位、300 余岗位，经就业微信群及班级转发，并列出校就业网等渠道 | 本地确实存在多渠道供给，而且学校已经在做人工整理 | 数字是校方报告，未经独立去重；不能据此断言学生漏看比例或现有整理无效 |
| 本科生研究计划有年级、导师审核、双向选择和项目支持条件 | 找导师之后仍需理解项目和参与条件；导师名单不足以完成任务 | 2025—2026 年通知不等于当前仍可申请，也不保证任何个人获得经费 |
| 形势与政策公开规则涉及讲座类别、累计要求和后续报告提交，课程预告另给选听入口 | 普通学期也有“已有义务—判断是否计入—记住进度—按时提交”的任务 | 不能证明多数同学不知道入口；个人记录也不是官方认定 |
| Handshake 2025 实习报告称 72% 的受访学生寻求实习是为了探索未来职业 | 至少在该调查覆盖的人群中，实习也服务于方向探索 | 平台及海外样本不能估算中国或中科大学生的需求比例 |

来源：[软件学院就业提醒](https://sse.ustc.edu.cn/2026/0916/c19741a753533/pagem.htm)、[本科生研究计划](https://www.teach.ustc.edu.cn/notice/notice-teaching/19630.html)、[教务 FAQ](https://www.teach.ustc.edu.cn/service/svc-student/13793.html)、[课程预告](https://marx.ustc.edu.cn/2023/0606/c30320a605104/page.htm)、[Handshake 报告](https://joinhandshake.com/network-trends/handshake-internships-index-2025/)。形势与政策规则适用性仍需按届别和最新修订确认；完整规则核对见需求地图。

这些材料支持开展任务衔接研究，尚不支持“全国普遍缺失”或“上线必有用户”。目前未测得问题发生频率、损失时间、使用意愿或需求规模。项目的必要性仍取决于：能否在demo中体现信息发现、理解与判断的帮助；持续维护投入在决定继续服务时另行判断。

## 2. 产品对象与任务

### 目标用户基线（2026-09-25）

**直接使用者：**初期面向中科大学生，帮助其个人发现、理解和选择校内外机会与支持资源。不同学科、年级和目标均在需求研究范围；当前本科案例较多，研究生特有任务仍属证据缺口。是否首版同时覆盖这些群体尚未决定。

**对象边界：**学生是当前直接服务对象；导师、课题组、院系、研究所、企业与活动组织方主要是信息对象或来源，不因此新增其发布、招生管理或招聘管理端。内容维护者承担供给工作，不等于用户社区；跨校信息覆盖也不等于已经决定首版服务全国高校用户。

| 可重叠的任务状态 | 触发与希望得到的结果 | 允许的结束方式 |
| --- | --- | --- |
| 探索者 | 尚无明确方向，想知道有哪些值得了解的选项 | 找到感兴趣的选项、暂存或只浏览 |
| 有目标的寻找者 | 已有兴趣或限制，想找到相关且可能参与的机会 | 找到入口，或确认当前没有适合选项 |
| 比较选择者 | 已有候选，想了解任务、条件、实际体验及差别 | 形成取舍或待问问题，也可暂缓／不参加 |
| 已有任务或要求者 | 已有研究、学习或培养要求，只缺适用支持、认定说明或办理入口 | 取得所需信息后直接离开，无需探索新机会 |

这四类是组织研究的任务状态，不是调查得出的固定画像或四类独立人群。同一人可以转换状态、同时有兴趣娱乐／综测／研究／就业等目的，不据年级安排发展路径，不要求先填写动机问卷。下表的具体场景均映射到这些状态，不重复建立人口分类。

| 决策层次 | 当前状态 |
| --- | --- |
| 产品整体对象 | 已明确：以科大学生个人使用为起点，研究跨学科、阶段与目标的机会／资源选择 |
| 信息范围 | 已明确：本校、外校、研究所、海外机构和企业等；按个人任务关联，不以地域判断优劣 |
| 第一条深入验证路径 | 已选择：AIDS学生的导师／科研机会探索；用户个人偏好是案例输入 |
| 首版优先用户与任务 | 尚未定稿；第一条试跑路径不自动成为唯一目标群体或最终首版范围 |
| 群体需求强度与覆盖充分性 | 尚未验证；需要不同目标的真实任务材料，不能从发起者需求推算全校 |

后续新案例优先补充任务条件与证据，不自动扩大服务对象、增加用户端或进入首版。只有证据影响对象边界或用户明确调整定位时才修订本基线；首版取舍在第6节更新。研究验证继续使用第8节唯一H/V清单。


初始服务对象是中科大学生，信息对象可来自本校、其他高校、研究所及海外机构。产品研究覆盖不同学科、年级和目标；以下按任务分组，不把专业当成兴趣，也不把所有学生都当作升学申请者。

| 用户状态与触发 | 希望取得的结果 | 条件差异及当前证据 |
| --- | --- | --- |
| 低年级或方向未定，想了解可以做什么 | 看懂真实任务，用小投入判断是否值得继续 | 职业模拟案例支持此类路径；本校真实探索行为未观察 |
| 准备科研、升学或选择实验室 | 比较研究内容、资格、培养方式和参与机会，形成待问项 | AIDS 首例及官方研究计划；跨学科和海外制度不能直接套用 |
| 以就业为目标，寻找实习或能力补足 | 分清岗位要求和个人缺口，找到可展示的准备产出 | 学院就业提醒、岗位页面及职业模拟；实际投递行为未观察 |
| 有竞赛、交换、文化活动等兴趣 | 判断时间、费用、资格和预期体验是否匹配 | 已有竞赛、交换和活动通知；案例存在不等于需求规模 |
| 已进入实验室或已有明确任务，但缺资源 | 获取文献、算力、设备或支持，无需重新探索方向 | 官方资源入口；真实个人权限与获取结果未核验 |
| 完成已有培养要求或处理日常通知 | 知道该做什么、是否计入、还差多少、在哪里办理 | 形势与政策公开规则；登录后的实际场次及个人进度未观察 |
| 时间、预算或资格不允许继续 | 尽早排除不适合的选项，保留以后再看或停止的理由 | 已有案例含限制；拒绝机会的实际过程仍待观察 |

同一人可以先探索、后比较，也可直接查资源或完成义务。需要准备的人可以得到指导，已经具备条件的人应直接进入官方渠道，不合适的人可以结束任务。

发起者的研究偏好为 AI、软件等，较少考虑 AI4S 和 AI for Math。这只用于首个 AIDS 导师案例。对其他同学不能默认相同偏好，也不能将十名导师的初筛当作产品覆盖范围。

当前样本偏向理工、研究和公开信息。非理工、志愿服务、研究生特有任务、残障或照护限制、近期相互矛盾的同伴经历仍缺证据。先保留这些缺口；下一轮至少引入一个不同目标的非作者参与者，不用无限增加画像替代实际观察。

### 参与动机与机会类型分开（2026-09-25）

用户补充的娱乐、共同参与和综测目的纳入共性任务分析，与学习、作品及发展目的并列，可重叠和变化。已在[需求地图](../constraints/opportunity-needs-map.md)补入掼蛋友谊赛、USTCPC与计算机系统设计赛事，以及学分认定通知和综测分享会线索。它们支持扩大取样，不证明动机比例；综测适用细则仍未取得。物理竞赛仅为样本，不再作为竞赛整体的代理。

V2/V3用同一比赛的不同目的、同一目的的不同比赛作对照，检查是否提供相应信息而不强加成长任务；关心认定者应区分用途、条件与未知。个人目的不明确时仍可浏览，不把所有机会套用同一“收获”标准。

### 社会科学文献补充：年级与任务不能互相替代

2026-09-24 新增[学生发展文献调研](../constraints/student-development-literature.md)，梳理九份研究材料，逐条记录样本、方法、阅读范围及推断限制。它们补充发展差异和动机证据，不提供中科大关注度排名，也不证明本产品有效。

本轮据此修正研究框架：年级可作为资格、时间节点和背景信息，不能自动决定兴趣或需求。实习、竞赛、学习路径及升学说明均保留为候选，按当前任务、基础和时间／资源限制检验；不采用“大一大二默认实习、大三默认升学”的固定路径。

学业适应和补基础保留为用户背景与研究议题；当前产品研究其中的支持发现、资源选择与获取困难，不将具体课程教学、练习反馈或知识掌握评估立为独立开发与验证任务。用户可以没有申请或机会探索目标而直接寻找支持。

后续取样应同时比较同年级的不同目标，以及不同年级的相似任务。升学选择保留研究兴趣、职业目标、风险与成本等差异；不把“更早确定”“参加更多”“成功升学”当作所有人的共同结果。家庭背景文献用于检查说明是否易懂，不用于强制收集家庭资料或推断个人能力。

### 现状任务过程：依据已有材料重建（2026-09-27）

下表是分析模型，不是已观察到的完整用户旅程。渠道存在和原文条件来自既有案例；步骤顺序、跨渠道搬运及可能困难是待核的解释，不赋予发生率、耗时或情绪数据。用户可跳步或在任何位置结束。

| 任务 | 触发与现有过程模型 | 原办法有效之处 | 可能需要帮助的节点与依据 |
| --- | --- | --- | --- |
| 跨机构研究探索 | 有兴趣／参与想法 → 通过RSTAR、搜索或转发找人／项目 → 看作品与参与条件 → 按需询问经历 → 决定联系、暂存或停止 | 官方页给研究和条件；熟人可补情境；已有科研平台提供发现入口 | 人物方向不等于招募，需把研究工作与参与途径关联；用户明确要求跨机构及体验考察，实际查找顺序未观察 |
| 实习选择 | 想了解工作或寻找岗位 → 招聘平台／学院渠道找选项 → 核对职责、资格和时长 → 按需问实际带教 → 申请或排除 | 岗位原文已有职责与要求；招聘平台已有筛选 | 需要分开硬性条件与优先项；MSRA历史材料可支持该区分，不能证明学生已误读 |
| 兴趣比赛兼顾认定 | 接触活动／与朋友讨论 → 查看形式、组队和投入 → 需要认定时核对院系规则 → 决定参加或不参加 | 赛事规则解决参与方式；同伴可帮助判断兴趣 | 赛事奖项不等于综测，院系适用文件可能缺失；未确认加分仍可因兴趣参与，不把认定设为共同目的 |
| 单次入口或资源查询 | 已有具体事项 → 搜索／问人／查指南 → 找到入口并检查必要条件 → 交给原服务 | 学生指南、课程预告和资源平台可能已经充分解决 | 入口足够时不加比较和准备；资源存在但权限不适用时，说明条件或替代。只支持识别适用性，不承诺获批 |

此模型支持选择产品介入位置，不用于证明新平台更快。后续遇到会改变设计的争议，可针对那个节点询问真实过程；不要求先逐行补齐观察才能进入设计。

### 任务中的顾虑与支持方式（2026-09-28）

[学生发展文献第10节](../constraints/student-development-literature.md)新增选择负担、自主支持、社会比较、职业信息实验和JobMate案例。它们支持分析机制，不构成科大学生心理画像：模糊偏好不等于不努力，多选项不必然造成负担，自报意向不等于实际行动。

对现有需求的补充解释：探索入口允许目标逐步形成；比较优先解释相关差异而非固定压缩候选数量；实际经历保留背景与约束，避免以成功个例定义资格；建议说明理由且允许拒绝；用户可纠正系统对个人条件的解释。不新增心理测评、真人模拟或社区需求，也不宣称缓解焦虑。这些是待评审的内容与交互建议，不是已验证效果。

本轮后续只在既有任务中观察是否出现误读、被迫继续或解释不适配。若来源、时间、名额或经费限制才是障碍，按事实约束处理，不归结为用户心理问题。

## 3. 现有解决方式与可借鉴经验

比较单位应是同一项任务，而不是功能数量。以下为公开资料对照；尚未完成登录体验或实际用户对照的部分明确保留未知。

| 现有方式 | 已有价值与证据 | 对本产品的约束及待验证空间 |
| --- | --- | --- |
| 学校、院系、导师与项目官网 | 权威条件和办理入口；本校已有就业整理、研究计划、交换服务与课程通知 | 应直接关联原入口；跨页面理解是否困难，要通过任务观察证实 |
| RSTAR本科科研实践平台 | 未登录首页已有导师、科研项目、资源、成果、通知和讲座入口；可见跨院系导师、具体项目任务与教程摘要 | 本校科研场景重点替代基线；不能以“缺少聚合入口”立项。导师检索与所查项目详情需认证，登录后比较／收藏／指导及跨校覆盖尚未验证 |
| 学生编写的指南与现场活动 | USTC不完全入学指南按具体问题提供资料；2026社团游园会已有集中展示、咨询和体验 | 纳入发现与直达任务的替代基线；历史活动不等于当前入口，编者自述不等于效果验证，详见需求地图本轮补查 |
| 群聊、公众号、小红书与熟人询问 | 校方通知证实群转发确实在用；发起者报告见过导师在小红书招生 | 未测覆盖率和更新速度；同伴经历可提供公开页没有的线索，不能假设聚合能替代询问；不默认采集私域 |
| 搜索＋表格／笔记＋通用 AI | 可按个人问题检索、解释、比较和保存，是必须正面对照的替代组合 | 目前没有证据证明本产品更快或更准确；需要用相同材料测试误读与一周后继续使用 |
| Stanford SOLO | 汇集研究、实习、公共服务等体验机会，支持订阅和申请／准备提醒，并将职业招聘、课程等引向相应平台 | 可借鉴跨机会发现和明确分工；不推断能够直接复制其校内数据整合，也无本地效果数据 |

## 4. 具体问题、原因与未满足需求

下表的“障碍”是已有材料提示的待验证解释，尚非全校用户的实测结论。重要性按可能影响的任务结果判断，不按未经调查的频率排序。

| 问题 | 情境与现有做法 | 障碍及原因假设 | 用户需要的结果与重要性 | 依据与未知 |
| --- | --- | --- | --- | --- |
| P01 找不到适用的信息入口 | 在官网、搜索、群转发间寻找机会或通知 | 来源按机构和业务组织，个人却按目标查找；也可能只是入口不熟悉 | 找到与自身条件相关的信息；若原入口已足够，应直接到达 | 就业提醒、课程预告；真实漏看和寻找成本未知 |
| P02 找到了但判断不了 | 看导师标签、论文题目或岗位要求，整理比较表 | 同一标签下的实际工作不同，资格、优先条件和建议容易混淆 | 解释差异并能取舍，避免误排除或误投入 | 导师主页、岗位案例；准确性与认知负担未测 |
| P03 知道方向却不知道如何开始 | 读介绍、问 AI、寻找课程或代码 | 介绍与具体能力证据之间缺一小步；也可能已有课程足够 | 理解相关基础、准备重点和可选起点，或直接复用现有指导 | Forage、准备卡走查；是否需要自建指导未知 |
| P04 有方法但资源不适用 | 尝试代码，再查算力、文献和设备 | 推荐行动隐含权限、费用或硬件前提，链接本身不足以解决 | 知道能否取得所需支持，以及无法取得时的替代或停止条件 | AlphaEdit、校算力和图书馆；实际获批未验证 |
| P05 离开后难以继续 | 在聊天、收藏、笔记中重新找理由与状态 | 信息变化和个人记录脱节；现有笔记也可能已解决 | 保留已作判断，回来知道什么变了、是否继续 | 返回流程假设；尚无具体丢失判断的任务记录，一周后收益未知 |
| P06 难以判断活动是否满足已有要求 | 查讲座，核对类别、累计和报告窗口 | 发现页面和培养要求不是同一任务，准备建议可能无关 | 判断是否计入、剩余任务及正确入口；不计入就停止 | 形势与政策规则；个人适用性和场次清单待查 |

具体例子：AlphaEdit 作者代码要求至少一张 A40 48GB GPU，这说明完整运行存在资源条件，并不表示了解该研究必须先有显卡。校超算注册需要负责人等前提，资源入口可以帮助判断下一步，但不能把学校拥有算力写成每位学生都能立即免费用。见 [AlphaEdit](https://github.com/jianghoucheng/AlphaEdit)、[超算注册](https://scc.ustc.edu.cn/portal/register)。

另一个边界是导师和实验室体验：公开论文只能支持对工作内容的初步理解，不能证明导师人品、日常指导质量或当前招生意愿。需求是取得足以了解实际情况的信息并形成个人判断；具体提问与私人记录只是支持办法，不能代替真实经历，也不能靠自动打分填补缺失事实。可参考 [CMU 的导师沟通问题](https://blog.ml.cmu.edu/2020/03/02/questions-to-ask-a-prospective-ph-d-advisor-on-visit-day-with-thorough-and-forthright-explanations/)。

### P07：看到了介绍，但不足以判断实际情况与个人适配

用户新提出的核心需求：供给方介绍不足以单独判断工作、指导、承诺兑现与个人适配。N11已提升为跨场景共性需求，与N05比较、N09私人记录关联；导师R6仅为其具体案例。比赛、交换／暑校、活动和课程／资源选择也应按需支持实际内容、体验与适配判断，不受长期协作条件限制。公开信息之外的内容可能尚不可得，不以AI猜测填补。

[实际体验研究与案例](../constraints/opportunity-needs-map.md)补入40人生命科学博士负面指导访谈研究、两人物理博士找组案例摘要、宾大工具包、NACE调查简报与实习建议。研究和指南支持分维度、多来源考察；不能估计本校发生率、判断具名对象，也未证明本产品改善选择。当前跨场景定位由用户确认；直接研究证据仍偏导师和实习，不能据此声称所有场景需求强度相同。中国本土经历、正式就业及比赛／交流／活动等场景的体验判断证据仍需补足。

候选最小帮助：用户关心的事项→相关自述／事实／经历→时间和情境差异→未知与待问→个人取舍。重点验证是否能提出更相关问题和避免无依据背书；不是找到更多负面内容、完成风险清单或生成综合分。若通用清单与笔记已足够，则缩小解释与关联功能。

### 需求成立依据复核（2026-09-26）

本轮只重审已有对话、文献和案例，不新增网页、访谈或效益数据。区分三件事：学生是否需要某种结果、现有办法是否留下缺口、我们是否有能力提供。近期导师内容样稿与来源复核主要回答第三件事，不能替代前两件事。

| 待帮助的任务 | 目前关于需要的依据 | 原办法已提供什么 | 还不能确认什么 | 当前需求判断 |
| --- | --- | --- | --- | --- |
| P01：从不熟悉的渠道找到相关机会／入口 | 发起者明确提出跨机构机会和不熟悉活动入口；案例证实信息确有不同落点 | RSTAR、就业汇总、教务栏目、学生指南及现场活动已有发现渠道 | 哪些学生在哪类任务仍难找，是否遗漏、原办法哪里不够；不能仅凭分散推导困难 | 保留发现为核心问题；跨来源整理的价值待按具体任务判断，不先要求新增平台或通知 |
| P02：理解实际内容并判断与自己是否相关 | 发起者希望了解研究方向、比较选择；作品／项目案例呈现有意义差异 | 原文、论文、FAQ、咨询和通用AI已有解释手段 | 学生理解障碍是术语、背景不足、条件关系还是候选过多；样稿清楚不等于实际帮助 | 保留理解与比较；解释深度随问题变化，不默认每次要并列表或所有细节 |
| P07：在介绍之外了解真实参与情况 | 发起者明确担心自我包装；既有指导研究和个人回顾支持检查介绍以外的情况 | 同伴询问、经验文章与课程评价已有实际情况线索 | 各任务中哪些体验影响取舍，原渠道哪里不足；缺资料是供给问题，不能当需求不存在 | 保留实质性的经历参考需求；不缩成只有提问清单，也不预先选公开评分方案 |
| P03／P04：需要开始时找到合适帮助 | 发起者提出能力准备与资源入口；文献提供学生差异旁证，案例显示权限等前提 | 课程、咨询、教程、工具和校内支持均已存在 | 具体卡点是不会做、不知道找谁、权限不足还是时间／费用不足；资源存在与适合个人是两回事 | 按需支撑，允许资源独立查询；不能由硬件门槛推出每个人都需训练计划 |
| P06：处理一项已有要求 | 发起者提到行策入口不熟悉；公开规则证明存在特定参与／提交要求 | 课程预告、规则与官方办理系统已承担部分任务 | “找到入口”“判断某场是否计入”“持续管理个人进度”是不同需要，后两者不能由第一个诉求直接推出 | 入口需求有直接诉求；认定困难仍需具体事件；自动进度管理保留为更弱的候选方案 |
| P05：恢复上次的判断 | 当前主要是研究者工作流推断及已有原型能力 | 收藏、笔记和表格已经能够保存 | 未取得实际反复查找或丢失理由的完整事件；是否需要系统主动追踪更未知 | 保留轻量保存候选，不将长期返回作为所有任务价值前提；提醒需求另证 |

“有直接诉求”仅指本次发起者明确提出，不等于群体代表性；“有文献旁证”也不等于当地发生率。上述判断不建立分数或强弱排名，不把兴趣娱乐与研究发展按重要性排序。当前没有足够依据声称多数学生遇到同一种障碍。

**优先需要回答的需求问题：**学生从什么起点开始，原办法最不满足的是哪一步，缺少的内容会不会改变选择，以及什么结果对本人已经足够。现有材料支持将发现、理解和实际情况比较作为产品研究主线；尚不支持认定所有场景都需要准备、记录、推送与进度管理。对实际体验的需求可以明确，但数据能取得多少仍单独留在可行性部分。

### 现有办法的作用与剩余问题：文献补证（2026-09-27）

[信息搜寻研究L10—L13](../constraints/student-development-literature.md)新增就业与日常信息行为证据。它们提示：多渠道可用于互补，而非本身就是失败；获取结果和判断相关性是不同任务；人际求助可能提供情境与信任支持。研究的年代、样本及读取深度详见原记录，不推算2026年科大比例或宣称产品已有效。

据此调整论证重点：P01问“有没有找到相关选项／入口”，P02问“已有信息是否足以理解并取舍”；不能把增加收录同时当作两者的答案。对既有办法先说明它完成了什么，再找剩余问题。只有原渠道尚未解决、且影响本人选择或行动的部分，才构成新增帮助的候选；未发现该缺口时允许结论为原办法足够。这里的缺口也可以是到达、理解或衔接成本，不要求内容独家。

对当前取样的影响：保留已经顺利解决的任务，比较不同渠道各自贡献；不把询问熟人归为产品失败、不因人际信息有用而重启社区。查找熟练度按实际过程了解，不按专业／年级贴标签。尚缺本地当前任务和现代搜索／AI使用证据，这些外部研究只增加需求解释依据，没有补齐它们。

### 对具体需求的判断

- **已纳入产品问题范围：**跨来源发现、理解参与条件、比较选择、了解实际参与情况，以及按需找到支持。这里“已纳入”是产品决策，不等于已测得普遍需求或已批准所有解决方案。
- **已有材料支撑的内容差异：**不同参与途径、硬条件与优先项、项目状态、规则用途及资源前提确实需要分别表达。待验证的是原网站是否已足够清楚，以及新增整理是否帮助学生。
- **明确仍有供给缺口：**具体对象的独立参与经历、部分现行院系综测文件和某些登录后资料。新增解释不能替代这些材料；但资料暂缺也不能把相应用户需要删除。
- **当前理由不足以直接建设：**统一黑红榜／总分、自动适配推荐、完整准备课程、综测计算器、全量提醒。它们各是可能的方案形态，不能由“想了解实际情况”或“怕漏消息”直接推出。

对于“黑红榜”的诉求，保留其背后的实质需要：学生可能需要供给方自述以外、足以影响选择的具体经历。有关失信或承诺未兑现的信息与普通偏好差异分开理解；不将所有问题都解释为个人不适配，也不由单条传闻给对象定性。官方平台能否承载这些信息需要实际查证。初期只考虑可公开引用的材料与个人私有记录，不以建设公众评价社区解决供给问题。

### 接下来哪些证据会改变范围

沿用第8节H1—H6/V1—V5，不再新增验证编号：先做一个跨机构发现任务和一个非科研选择任务的材料对照，同时检查体验来源能取得到哪层及整理成本；之后邀请不同目标的自愿参与者观察其真实任务。先用公开材料能查明的问题不发问卷，尚未了解实际过程时也不先做功能偏好投票。

这项排序按对产品取舍的影响确定，不代表科研需求最大。每项执行须留下实际输入、原渠道已有结果、候选结果、未知项与对取舍的影响。若只有入口难找就优先做导航；若材料足够却难理解则检验解释；若关键信息尚不可得则先缩承诺；若已有工具同样有效则撤回重复功能。桌面材料、人工走查与真实参与者证据分别记录。

### 问题影响与可解决边界（2026-09-27）

重要性按后果及产品可作用程度判断，不按材料条数、风险措辞或想象中的发生频率判断。下列后果均是可能性，不是已统计事件。

| 问题 | 可能影响 | 信息产品能改善的部分 | 无法代替的条件与取舍 |
| --- | --- | --- | --- |
| P01发现、P02理解 | 漏掉相关选项，或因误读资格排除／投入不适用对象 | 找到选项、解释相关性、区分资格性质与未知 | 名额、录取与接收意愿由外部决定；不以发现数量证明任务完成 |
| P07实际参与判断 | 只凭介绍形成不充分预期，参与后才发现重要差异 | 关联具体经历与记录、保留情境冲突、帮助确定待问事项 | 无法保证经历齐全、代表性或将来兑现；不生成对人的综合好坏结论 |
| P03准备、P04资源 | 在不必要准备上投入，或采取资源上不可行的行动 | 说明必要性与可选性，连接适用支持 | 经费、时间、设备与审批不足不能靠解释消除；允许换路径或停止 |
| P06规则与入口 | 到错办理处，或误以为活动符合个人认定 | 连接准确入口，按适用原文解释规则 | 未取得规则不做个人认定结论，学校裁定不由产品代替 |
| P05接续 | 重新整理理由，或继续依据旧状态判断 | 私人记录和来源状态可帮助接续 | 当前直接事件证据较弱；不据此优先建设推送、自动进度或同步 |

因此优先解决发现与判断，并在关键条件上避免误导；准备和资源只补当前卡点，保存作为低承诺候选。一次性查询即使影响较小也可有价值，不因科研决策后果较重而排除轻任务。

## 5. 产品价值与定位

定位：帮助学生独立发现适用机会与资源，理解选择差异，按需准备，并回到官方渠道行动的个人工具。价值在于一次任务中减少重复整理、错误理解和无法执行的建议；这些收益目前是待验证主张。

| 从问题推导的价值 | 候选实现 | 能推翻或缩小该主张的结果 |
| --- | --- | --- |
| P01：更容易找到适用入口 | N01–N03 搜索、条件与关联 | 原站或搜索已经同样容易找到，额外平台增加步骤 |
| P02：更容易解释差异并取舍 | N04–N05、N11 条件解释、比较和待问项 | 解释不准确，或通用 AI＋笔记已满足任务 |
| P03–P04：知道一个可执行行动及所需支持 | N06–N07 可选准备与资源 | 建议超出基础、资源不可得，或原服务已有完整指导 |
| P07：考察实际体验并形成有依据的个人判断 | N11关联来源与待问、N05比较、N09私人记录 | 关键经历无法取得，或通用清单与笔记已满足；不能承诺揭示隐藏问题 |
| P05：能接续原先的判断 | N08–N10 状态、保存及可选提醒 | 一周后不能恢复理由，或现有收藏已足够 |
| P06：正确完成或排除已有要求 | N13 适用性、进度和入口 | 规则无法可靠适配个人，或原系统已完整解决 |

聚合价值不以内容独家或功能无人做过为前提。原文已有信息，只能说明我们应尊重并复用来源；如果跨来源组织、适合起点的说明或相关经历能帮助学生发现／理解／取舍，仍可能值得使用。反过来，来源分散或原站缺某个按钮，也不足以证明新产品必要。比较的是学生实际完成任务的过程，不能只比较功能数或让熟练研究者代表普通用户。

是否便利不必只用秒数表示：找到原先未接触但相关的选项、理解关键差别、形成更具体的判断或直接到达入口都可成为可观察结果；本轮尚未取得这些用户结果。不要求一项工具击败所有替代办法才有价值，也不把“有信息可整理”写成使用理由。

单个人使用应能取得上述结果，不需要他人发帖或活跃。社区不属于本期功能和预定后续阶段。录取、找到工作、获得经费也不宜作为首版验收，因为它们受大量外部因素影响。

2026-09-25 用户确认主次：**信息发现与选择为核心，准备指导为重要支撑，资源连接为辅助**。准备重点、理由和可选路径服务自主判断；具体章节教学与知识效果测验不属于当前范围。资源可以独立搜索，跨场景研究继续。详细边界与新增工作判据见[产品概览](overview.md)。

## 6. 整体范围与首版优先级

整体研究保留科研／升学、实习／就业、竞赛、交流、活动／通知和资源需求。跨地区、机构及学科是覆盖方向，不是第一版必须全面收录的承诺。

**首个验证切片**仍为 AIDS 导师探索：从个人偏好理解代表工作，比较候选，确认未知招募条件，选择可选准备或资源，再进入官方渠道并保存结果。选它是因为有明确个人任务和已有材料，可以深入检查流程；不是因为已证明导师需求最大。

### 当前范围建议：共同基础与按需能力（2026-09-26）

本节将已确认方向与候选实现分开。以下不是学生需求强度排名，也不是首版开发批准；真实任务复盘尚无新增回答，不因此停下已有证据的范围整理。

| 层次 | 当前结论 | 对实现范围的含义 |
| --- | --- | --- |
| 已确认的产品原则 | 个人使用，发现／理解／比较为核心；准备与资源按需；跨机构跨学科研究；自主停止；办理回原渠道 | 不再反复论证是否需要社区或是否只有导师场景；不等于下面每个候选功能都已确定 |
| 优先验证的共同基础 | 从模糊兴趣或具体问题找到相关对象／机会／支持，了解实际内容、关键条件、状态和原入口；N01—N04、N08，N12提供基本维护 | 用真实材料验证发现与理解；只建立该任务有用的关系。简单活动无需补出论文、导师和成果字段；维护可先用文件，无需后台 |
| 按任务需要组合的能力 | 候选比较与实际体验考察N05/N11、准备重点N06、资源匹配N07、个人保存N09 | 不强制统一顺序；“可选”是对用户而言，不表示这些需求价值较低。需要深入判断时仍是核心；只找资源的人可直接进入资源路径 |
| 首版尚待决定 | 通知N10、培养要求与个人进度N13、跨设备、收录规模、自动采集及指导生成方式 | 不能从有收藏推导必须通知，也不能从已有规则推导必须建设进度系统；保留候选，按实际任务与供给决定 |

**候选首版建议：**先用选定的导师／科研案例交付一次完整的发现与选择帮助，研究跨机构机会和实际任务，按需关联准备、资源及个人理由；同时用轻量兴趣和入口直达案例检验它是否依赖科研背景或过长流程。首例沿用用户选择，不声称已证明科研需求最大；轻量案例用于反证与修正，不要求首版立即铺开活动库。最终上线机会类型与数量仍未决定。

| 任务自然结束 | 最小有用输出 | 何时才追加帮助 |
| --- | --- | --- |
| 找到所需入口 | 对应事项、当前可确认状态及原站落点 | 用户还不清楚条件或使用方式时，补必要解释 |
| 发现有兴趣的选项 | 具体会做什么、影响本次选择的时间／费用／对象条件，允许未知 | 想比较或了解实际体验时再深入；不强制填写目标画像 |
| 完成一次取舍 | 与个人问题相关的差异、已知依据、待确认项及可选下一步 | 用户确需准备才给重点与资源，愿意留待以后才保存 |

本轮修正N06中的“产出”要求：准备说明可解释相关基础、可选探索方式和为何需要；不要求每次帮助都有作品、练习或可考核结果。N03的人物／作品关系只在科研等适用情境出现，不作为所有内容的共同必填模板。N11仍保留实际体验和承诺兑现的价值，不因难采集就以官网摘要代替；拿不到的部分明确未知。

已有六条样本原型只是验证工具，不能因为已实现而保留某功能。P1研究面保持广；首版可以窄，两者分别判断。没有参与者时，可准备有限内容样本和交互方案，并保留收益、维护成本与用户覆盖风险；不能把这些风险写成已通过，也不以全部长期验证完成为内容原型的前提。

### 可选产品方案与优先级理由（2026-09-27）

以下为方案比较和推荐，不是用户效果测试，也不构成新增功能批准。比较的是能解决哪些任务及承担什么维护负担，不给缺乏依据的量化评分。

| 方案 | 适合解决什么 | 代价／剩余缺口 | 当前取舍 |
| --- | --- | --- | --- |
| 不新建产品，继续原站＋搜索／AI＋笔记 | 已知入口、熟悉领域、自主整理能力足够的任务 | 每次跨来源关联由个人承担，但实际负担未测 | 保留为有效替代和对照；不能预设原办法失败 |
| 入口导航 | 单次查询与外部办理 | 深入比较和具体工作解释仍需自行完成；维护链接成本相对有限但未计时 | 纳入轻任务终点；不作为全部产品的唯一形式 |
| 精选机会资料库 | 发现候选、查看条件与原文 | 需要选源、去重和更新；仅复述可能不足以帮助判断 | 作为供给基础，不以收录数量作为价值终点 |
| 有限资料＋按需关联比较 | 跨来源发现，理解工作、条件和经历依据，再作个人取舍 | 增加解释、关系维护与经历处理负担；不保证每条都有完整信息 | 推荐首版组合，直接服务P01/P02/P07；简单任务可只用导航 |
| 全平台自动推荐＋推送／进度体系 | 假设中的大规模持续跟踪需求 | 来源、个性化、权限及更新依赖更大，返回需求尚弱 | 首版暂缓，不以“更完整”为由纳入 |

首例选择科研，是已确认试用起点且能检验较深的发现／判断任务，不是人群规模排名。跨场景收益预期来自共性任务，具体覆盖仍要按内容供给决定。若选定任务的关键判断只能依赖拿不到的经历，先缩小可回答的问题并说明未知；若只是找入口，直接采用导航，不强行套比较流程。

**成果目标主次：**首个切片首先帮助用户发现与自身问题有关的候选，并理解足以决定是否继续的差异；实际经历依据属于需要时的判断内容。准备与资源支撑这次选择，私人记录支撑之后接续。申请成功、参加更多活动和频繁回访不作共同目标。

## 7. 功能与使用要求

完整行为和案例验收见[需求基线 N01–N13](requirements.md)。需求与功能的关系以第四、五节为准，开发前需根据观察删减候选，不将全部编号自动纳入首版。

共同要求如下：

- 可从探索、指定对象、资源或已有要求直接进入；浏览不以长问卷或精准方向为前提。
- 分开呈现人物、作品、实际机会和资源。导师主页不等于招生公告，历史案例不等于开放报名。
- 区分硬性资格、优先条件、建议及未知。没有公开答案时说明待确认，不自动补成正向或负向结论。
- 准备可以跳过；不符合、已过期或投入不可承受时允许停止。即使资格符合、资源可得，用户也可以只了解、暂缓或不参与，无需解释理由；不能强塞学习任务。
- 资源说明用途、资格、费用性质、状态与入口。校方额度上限不写成免费赠额；审批是否成功回官方确认。
- 个人理由、待问项和进度只供本人使用；外部办理跳转原站，不收第三方密码。真实个人数据的存储、删除和跨设备方案须在实现前确定。
- 阅读要支持长文本、窄屏、键盘与明确链接；前端遵守[已确定的 UI 规范](ui-system.md)。无指导时，已发布信息仍可阅读。

### 研究偏向复核与纠正（2026-09-26）

结论：范围声明已覆盖多类任务，但证据深度、验收例子和最近执行仍偏向科研／升学、公开正式项目、目标明确且愿意深入比较的用户。这是对现有文档的分析，不是新取得的学生调查结论。非科研案例已经存在，问题在于其研究深度与决策影响不足，不能简单说“只研究了导师”。

| 当前偏向及文档依据 | 可能造成的以偏概全 | 纠正方式 |
| --- | --- | --- |
| 科研案例牵引方案：N03用人物／作品关联，N04以论文与设备验收，N07以算力验收；首条完整路径来自导师探索 | 把每类机会都设计成研究方向、能力准备、资源和长期记录的组合 | 保留科研深例；用娱乐／共同参与、单次入口、模糊探索等不同任务检验哪些步骤实际需要，不让换名后的科研流程充当跨场景证据 |
| 供给方公开材料偏向：已执行走查主要是通知、FAQ与组织者总结；经历证据不足 | 官网写得清楚被当成学生已经了解，或公开条件被当成实际体验；官网资料丰富的机构更容易被收录 | 区分“能否发现”“发现后能否理解”“实际是否如此”；记录学生实际渠道及询问过程，缺体验不等于不需要体验，也不自动扩大到私域采集 |
| 主动、目标明确、善于检索者偏向：近期任务预先给了时长、方向和已知机构 | 低估不知道关键词、不知道有哪些选项、靠偶然转发发现的人；作者定向搜索不能证明新手发现能力 | V1保留模糊起点及既有渠道，先看学生如何开始；V2非作者还应检查任务状态差异，不只换一个专业 |
| 深比较与持续推进偏向：首条路径含比较、准备、资源、保存；N06写准备产出，H5安排返回 | 把浏览、一次性查询和纯兴趣参与视为不完整使用；可跳过的声明不能证明默认流程足够轻 | 入口直达、了解后离开与暂存都单独算完整结果；准备、深入考察、保存和返回按任务决定，不设共同必经顺序 |
| 规则正确性与维护偏向：近轮细化日期、资助、资格和两条AI计时；第8节先排供给工作 | 用可核对的字段问题替代需求重要性，产品逐渐变成通知复述与条件核验；忽略有趣、内容吸引力和实际参与感受 | 字段复核作为质量支撑；下一项优先补实际发现／取舍任务和体验问题，维护工作限于支撑所选任务，不继续独立扩张 |
| 方案与替代基线偏向：N01—N13已较细，背景尚缺真实卡点；原站＋搜索＋AI＋笔记是研究者组合 | 围绕既有功能寻找证明，或拿熟练作者的工具组合当所有学生的替代办法；信息外的费用、时间、名额和关系障碍被误当信息差 | 先还原当前做法、满意之处与最关键障碍，再决定是否需要功能；同时保留原办法已经足够的任务。熟人帮助不自动等于产品社区需求 |
| 验证流程偏重：多处重复独立对照、一周返回和维护计时，历史进展与当前状态叠加 | 让需求分析变成全部验证过关后才能推进，或用流程严谨掩盖尚未形成取舍 | 八部分论证与关键范围决定是分析交付；长期返回只影响相应功能，长期供给在试用中继续。未知可显式保留，不虚构完成，也不无限延迟有限原型 |

有意边界不属于待纠正偏见：科大作为初期服务对象、个人使用、发现与选择为核心、指导按需、办理回原站均为已确认选择。不为追求表面均衡改成覆盖所有校园问题，也不要求每种人群同样数量的案例。外部高校经验和文献按人群、任务及情境可比性采用，可支持共性需求；本地规则、精确比例与本产品效果分别核对。第一例偏深可以接受，但不能由其推导全产品统一流程或需求排序。

下一轮最小补证沿用V1—V5：优先检验模糊探索／轻量兴趣、明确目标的深入选择、已有要求的单次入口三种不同任务机制；这些是取样方向，不是已证实的三类人群。先记录真实起点、原办法、满意和不满意之处、影响取舍的信息与自然结束点，再决定是否需要比较／指导／保存。现有导师深例可复用；其他任务有自愿参与者时观察，没有时只做标明为构造的公开材料准备。一个不同目标参与者只能暴露反例，不能证明覆盖充分。

## 8. 可行性、验证和完成条件

### 任务成果的判定标准（2026-09-27评审建议）

本节细化目标的含义，不报告通过结果，也不要求全部任务同时验收。与H1–H6/V1–V5沿用同一套定义；任务挑选后，在展示方案前固定影响选择的关键事实及来源。不能事后只挑表现好的例子，不能为了补数字虚构节时阈值。

| 成果目标 | 对单次任务而言“足够”的结果 | 不足或不可接受的结果 | 判断方法 |
| --- | --- | --- | --- |
| 发现相关选项（H1） | 能指出值得继续了解的候选及与当前问题的联系；无匹配时能理解覆盖限制并决定改条件或离开 | 编造候选、把未知资格当符合；用更多结果冒充相关性 | 依据用户表达与源条件核对理由。若主张新增发现，另与其原渠道相较；无结果处理正确只算可用性，不算发现增量 |
| 理解并取舍（H2） | 能说明影响本次选择的差异与待确认条件，决定继续、换选项或暂停 | 把优先项当硬门槛、历史状态当开放、不同项目条件合并，进而影响选择 | 使用同一材料核对关键条件；不要求背全字段或与评审者选同一候选 |
| 考察实际情况（H3） | 能分清介绍、可核对记录、个人经历与未知，形成有依据的判断或具体待问事项 | 将自述当独立背书、以缺信息判差评、人格评分或虚构经历 | 核对具体来源和时间情境。仅形成问题可算部分帮助，不能声称已提供实际体验证据 |
| 适用支持与轻任务（H4） | 找到所需入口；需要帮助时知道可选起点、资源前提或不可用原因；可以结束 | 为不参加者追加任务；把审批资源写成立即可用；入口错配 | 核对外部落点和条件；用户不参与不是失败，外部是否获批单独记录 |
| 接续判断（H5，仅采纳保存时） | 回来能找到原候选和自己的理由，并分清原判断与新的状态 | 笔记丢失、源失效静默删记录、过期状态被当最新 | 实际返回检查恢复情况；模拟刷新只证明存储行为，不证明长期需要 |

对拟展示材料，已知且会改变决定的事实错误必须修正后再交付；不因此承诺全网事实零错误。使用者持续误解则修改解释或缩小功能，再检查相关任务。成功不取决于选择了多少机会，也不证明全校效果。

供给验收仍沿H6处理：首批来源能说明责任与更新范围，经历缺口如实保留；覆盖超过人力时缩规模。具体预算和负责人待实施计划确定，不用分析文档替同伴作承诺。

### 验证任务与决策（V1–V5统一定义）

H6及V5中的周期更新、人力预算仅在决定持续服务时执行，demo仅检查本批来源可得性、提取结果和必要核对。V4真实返回用于效果验证，功能重开另作demo检查。

V编号表示验证目的，不绑定具体场景；导师、职业探索、竞赛等是执行案例。2026-09-25起本表替代需求基线中早期按场景命名的V表。以下是计划，不是完成结果。

| 验证 | 对照与记录 | 决策用途 |
| --- | --- | --- |
| V1 发现、判断与比较 | 发现环节记录起始目标、渠道和候选；解释环节使用同一材料对照原站／搜索笔记、独立通用AI及本产品；分别记录误读、理由、求助和用时 | 分开判断新增发现与解释增量；按H1–H3删减或保留 |
| V2 不同目标与场景 | 至少一位目标不同且未编写材料的自愿参与者完成真实任务；含非导师／就业案例，具体考察维度随任务变化 | 判断是否依赖作者知识、科研背景或过度深入 |
| V3 适用支持与自主停止 | 比较原入口与最小指导／资源补充；包含条件不允许、符合但不愿参加、仅找入口的情况 | 能否找到适用支持并自主决定；不自动追加任务 |
| V4 返回与个人记录 | 保存后在一周后自愿检查三种方式能否恢复理由和状态；未返回如实记录 | 判断保存与更新需要；模拟重开只算交互检查，不测长期留存 |
| V5 来源供给与维护 | 按记录计首次整理、复核和一次更新耗时及错误；明确来源、规则、纠错责任与人力预算；查看实际体验信息能取得到哪层 | 决定覆盖、深度及承诺；更新演练与真实变化分开，自动化不是责任人 |

V1–V5作为一组验证计划保留上述约束，不要求每项单独操作都同时包含全部约束。例如独立完成一条来源计时，可以记为V5局部证据，但不能据此宣称V1–V5或P1完成。作者走查、构造场景、参与者观察和独立AI对照分别记录。

对照需记录模型版本、日期、输入材料、联网条件和实际输出；作者自己重写不能算独立AI基线。控制顺序与熟悉效应，记录先前知识；小样本用于暴露问题，不推算全校比例。成功可以是理解差异、换选项、暂停或不参与，不能仅以“觉得有用”、申请数量或频繁返回判断。不规定未经讨论的节时百分比；执行前确定可核对的关键条件、错误类型与可接受输出，时间只作辅助证据。

### 实际任务复盘：执行方式与当前记录（2026-09-26）

下一步用真实事件决定是否保留候选能力，不继续用功能喜好投票或新增新闻报道替代。2026-09-26已向发起者询问最近一次实际查找的起因、原渠道、结果和不满意处；当前尚未收到该次复盘回答。下面是可直接执行的观察方式，不是完成结果。不联系第三方，不索要聊天原文、姓名或账号。

**先听原过程，再展示方案。** 优先选择对方还记得的一件具体事件，任务可以已解决、放弃或没有明显困难；先不用“信息差”“指导”“比较页”等产品词引导回答。

| 顺序 | 中性提问／观察 | 记录目的 |
| --- | --- | --- |
| 起点 | 最近一次想找什么？什么事情让你开始？当时已经知道什么，不确定什么？ | 区分目标先有、接触后有兴趣、仅需一个入口；不强迫归类或明确职业方向 |
| 原过程 | 最先从哪里得知或查找？后来做了什么？有没有问别人？ | 保留真实渠道及原办法有效的部分；回忆时间标为估计，不当实测 |
| 取舍 | 哪条信息影响了继续／不继续？还有什么没弄清？如果已经足够，是哪一步足够了？ | 判断缺口在发现、理解、经历、资源，还是费用／时间／名额等非信息障碍；不预设一定有痛点 |
| 结果 | 最后做了什么，或在哪里停下？现在是否还需要帮助？ | 区分信息任务完成与申请／参与完成；停止不算失败 |
| 适用时的小对照 | 得到原过程后，仅针对实际未解问题提供最小整理，请对方解释现在如何判断、还缺什么；原办法足够则不加内容 | 检查具体新增帮助与错误，不能只问“喜欢吗”；已听过答案后的表现存在熟悉效应，不称严格独立实验 |

一次回忆可揭示具体事件，但不能证明发生频率或因果收益；若对方自愿现场复走才记录现场行为。独立AI对照、计时或一周返回仅在相应问题需要时另执行，不要求一次访谈完成V1—V5。先由真实问题确定补充材料，再核对当时／当前时效，不拿历史活动冒充现在的选择。

**已有对话可用到什么程度：**发起者明确表示偏研究，兴趣包括AI／软件，较少考虑AI4S与AI for Math；提出跨校／研究所／海外信息、了解真实培养情况和准备重点的需求。这是一个具体个人的诉求证据。尚未描述一件完整的实际查找事件，因此不能补造原先使用小红书的顺序、耗时、错失机会或最后选择。提到“老师喜欢用小红书招生”也不等于本人已通过该渠道找到候选。先前构造的两个月科研／两周文化交流限制均不是本人确认条件。
