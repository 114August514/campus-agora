## 交接摘要

**产品是什么：**面向大学生个人的机会发现与选择工具，初期服务中国科学技术大学学生。连接本校、外校、研究所及海外的机会与支持，帮助用户发现选项、理解实际内容、比较适配性，并在需要时找到准备重点与资源入口。

**核心价值：**将分散且层次不同的信息组织成与个人当前问题有关的选项和判断依据。除了“有没有机会”，也帮助理解“实际做什么、条件如何、参与体验有哪些依据、是否值得自己继续了解”。

**整体范围：**科研与导师、升学、实习、竞赛、交流、活动通知及支持资源。个人可直接使用，不依赖社区活跃。社区仅为潜在扩展，不是首版功能或预定阶段。

**首版建议：**以有限来源的导师／科研发现与比较作为完整切片，按需提供准备和资源连接、轻量私人记录；用入口查询和非科研样例检查共性结构。AIDS学生的导师探索是第一个真实试用案例，不代表全体用户或产品上限。

**当前成熟度：**背景、对象、问题与需求已形成可评审论证，足以继续任务和信息结构设计。首版范围仍是建议；用户实际收益、长期供给成本和维护责任未确认。本次希望同伴重点评审价值、范围与任务是否合理，而非先确定全部技术选型。

## 1. 问题背景与立项依据

高校已经提供大量机会与服务，不能以“学校没有平台”作为前提。信息往往按院系、机构、项目和业务发布，而学生可能按个人兴趣、时间、资格或参与目的查找，还需要理解介绍与实际参与之间的关系。

已有材料提供三个值得解决的问题方向：跨来源发现适用选项；理解任务与条件差异；结合介绍以外的信息形成个人判断。它们不能直接证明所有学生都困难，也不能证明一定需要一个新平台。

| 已有依据 | 支持的判断 | 适用限制 |
| --- | --- | --- |
| 科大软件学院2026年就业提醒报告整理20余家单位、300余岗位，并通过信息群和班级群转发 [S1] | 本地有多渠道供给，也已有人工汇总；应在既有服务基础上讨论增量 | 数字为学院自述，非独立核验；不是学生需求规模或漏看率 |
| RSTAR未登录首页的既有走查发现导师、项目、资源等入口 [S2] | 本校科研聚合已经存在，须纳入替代方案 | 2026-09-25观察；登录后的能力和跨校覆盖未核实 |
| 2010年美国25校8,353份自愿问卷中，41%报告相关性筛选困难、18%报告选择信息源困难 [S3] | 信息获取与相关性判断是不同任务，不能仅以收集条数衡量价值 | 回应率7.4%，自报且年代久；不推算当前科大比例 |
| 国内18名求职成功毕业生访谈研究讨论线上线下渠道组合 [S4] | 多渠道也可能有效互补；产品要保留原渠道价值 | 仅读摘要，有成功者选择偏差，不证明本产品优于原办法 |
| 发起者明确提出跨机构导师探索、实际培养体验、准备和资源需求 | 支持首个试用任务及产品方向取舍 | 属于一个人的直接诉求，不虚构完整查找经历或全校共识 |

**立项判断：**有依据围绕发现、理解和选择开展有限产品试验。采用已有证据，无需重新证明同一问题；产品比搜索、原站、AI与笔记组合好多少，留待实际任务检验。

## 2. 产品对象、任务与使用情境

初期直接使用者是科大学生个人；信息范围跨机构、地区和学科。教师、项目方、资源提供者是信息对象，不因此增设机构管理端。维护者负责供给，是支持角色。

| 用户当前任务 | 典型情境 | 用户需要的结果 |
| --- | --- | --- |
| 探索可能性 | 兴趣模糊，不知道具体方向或关键词 | 看懂一些具体活动／工作，找到愿意继续了解的选项 |
| 寻找和比较 | 已有研究、就业、兴趣等目标 | 找到相关候选，理解差异、限制及未知，形成自己的理由 |
| 判断实际参与情况 | 招生或活动介绍不足以回答日常体验 | 结合具体经历与可核对记录了解指导、任务、投入和承诺兑现 |
| 判断如何开始 | 对某机会感兴趣，但不了解基础与准备 | 分清必要条件、优先条件和可选准备，知道适用的起点 |
| 寻找支持 | 已有任务，缺算力、文献、课程、设备或咨询 | 找到适用资源及获取条件，不必先走机会探索流程 |
| 处理已有要求或通知 | 只想找到行策入口，或了解某比赛是否计入认定 | 找到正确入口和适用规则；简单任务可以直接结束 |

用户可在任务之间转换。年级和专业可影响资格，不能据此指定人生路径；兴趣、朋友共同参与、综测认定、研究与就业目的可以并存。无须填写固定动机问卷。

首例来自AIDS学生的导师探索：本人偏研究，倾向AI／软件，较少考虑AI4S与AI for Math。偏好用于该案例，不固化为全产品筛选规则。当前材料偏理工、研究及公开信息；非理工、不同支持需求和实际参与者行为覆盖不足，应在相应扩展决定中处理。

### 当前任务过程与介入位置

以下由已有渠道和案例重建，属于分析模型，未观察到完整的个人操作顺序，不附虚构耗时或痛点频率。

| 任务 | 当前过程模型 | 产品可能介入的位置 |
| --- | --- | --- |
| 科研／实习选择 | 形成兴趣 → 搜索、平台或转发找人／岗位 → 看工作与条件 → 按需问经历 → 联系、暂存或停止 | 跨来源发现、把工作与参与途径关联、解释影响取舍的条件 |
| 兴趣比赛兼顾认定 | 接触比赛／朋友讨论 → 看形式与组队 → 需要时查院系规则 → 自主决定 | 同时理解兴趣与认定；没有认定结论仍可因兴趣参加 |
| 单次入口／资源 | 已有事项 → 查找或问人 → 看入口及必要条件 → 交给原平台 | 入口足够即结束；权限不适用时说明前提或替代 |

原渠道的官方条件、人际情境与办理能力应保留。完整模型见[需求分析](needs-analysis.md)的“现状任务过程”小节。

## 3. 现有解决方式及产品增量

| 现有方式 | 已经解决的事情 | 本产品可以探索的增量 |
| --- | --- | --- |
| 学校、院系、导师和项目官网 | 发布条件、状态、原始材料和办理入口 | 跨来源发现，关联人物、具体工作与参与途径；办理仍回原平台 |
| RSTAR [S2] | 已有本校科研项目、导师和资源入口 | 跨机构探索和个人比较值得检验；不能断言其没有同类能力 |
| 搜索＋通用AI＋笔记／表格 | 自主检索、解释、比较、保存 | 减少重复整理并保留依据；增量尚无独立实测 |
| 群聊、公众号、小红书及熟人询问 | 传播信息、提供情境和参与经历 | 保留合法可用来源及上下文，连接后续询问；不承诺替代人际判断 |
| Stanford SOLO [S5] | 多类型机会发现，并与其他专业平台分工 | 可借鉴统一发现入口和外部办理，不以跨类型聚合作独创性主张 |
| Handshake [S6] | 职位筛选、保存搜索和提醒 | 通用列表与提醒已有成熟替代，需要围绕学生具体任务体现价值 |

对比应围绕同一任务。原服务已经满足的部分直接连接；额外整理没有帮助时减少内容。信息不必独家，但不能只凭页面更多或文案更长宣称更有用。

## 4. 未满足需求与原因判断

以下为结合诉求、文献和案例形成的需求判断；障碍发生频率及影响程度未实测。沿用现有P编号，避免新建平行清单。

| 问题 | 原因或障碍假设 | 所需结果 | 依据性质 |
| --- | --- | --- | --- |
| P01 难发现适用选项 | 信息按提供者分布，个人按目标查找 | 找到相关且可进一步了解的机会或入口 | 个人诉求、实际供给、多渠道文献 |
| P02 难理解和比较 | 方向标签过粗；硬性资格、加分项和建议混在一起 | 理解实际工作与关键差异，不因未知被误排除 | 个人诉求、导师／项目／岗位材料比较 |
| P03 不知道如何开始 | 缺少从当前基础到任务的必要说明 | 知道准备重点、理由与可选起点 | 个人诉求与准备材料走查；指导形式待设计 |
| P04 资源不适配 | 权限、费用、设备或时间前提不匹配 | 判断资源能否使用，找到替代或停止 | 算力等公开条件 [S8]；未验证个人获批 |
| P05 离开后难恢复判断 | 记录与信息状态脱节 | 保留候选和自己的理由 | 工作流假设；尚无完整的丢失判断事件 |
| P06 不清楚是否满足已有要求 | 活动介绍与适用制度分开 | 理解是否计入及正确办理入口 | 公开规则／通知 [S9]；自动进度不是已证实需求 |
| P07 介绍不足以判断实际情况 | 供给方自述难独立回答日常体验、支持与兑现 | 按任务结合经历、记录和未知作判断 | 个人明确诉求、导师沟通指南 [S7]及既有研究；各场景供给不均 |

P07适用于导师、实习、竞赛、交流、活动及资源。具体问题随场景变化，例如导师看指导与研究任务，比赛看实际投入与组织支持。不能仅用提问清单替代真实信息，也不能以论文数量推断人品；没有经历材料时明确未知，不用AI补造。

### 问题影响与产品能力边界

P01/P02可能影响选项发现或资格判断，P07可能影响实际参与预期，P03/P04可能带来不必要准备或不可执行的行动，P06可能导致入口／认定误判；这些是后果分析，不是发生率数据。P05接续目前直接事件依据较弱，不能支撑优先建设完整跟踪体系。

产品能改善信息组织、解释和判断依据；不能消除名额不足、时间冲突、经费缺口或替代接收／审批决定。重要性按可能后果及可作用程度讨论，不按案例数量排序。科研后果可能较重，也不意味着轻量查询没有价值。

## 5. 价值定位与使用原则

核心是**发现、理解和比较**；准备指导帮助判断下一步；资源连接帮助取得支持，也允许独立查资源。产品交付可复用的个人工作流，不只是导师名单。

已确认原则：

- 初版只服务个人使用，无社区发布、公开评价或社交冷启动要求。
- 用户可浏览、保存、改变方向、暂停或拒绝机会；符合条件也不必参加。
- 准备内容按需出现，不提供统一成长任务、欠缺排行榜或默认催促。
- 学校已有资源与外部资源按实际适配选择，官方身份不等于对每人最优。
- 官方义务与可选建议分开；申请、预约、报名由原平台承担。
- 实际经历要保留来源、时期和背景；私人判断不公开，不做人格评分。

不作未验证承诺：节省固定比例时间、提高录取率、全面消除信息差、降低焦虑或持续覆盖全部机构。

## 6. 范围与优先级建议

优先级依据是已确认目标、首例材料准备程度和完整任务所需能力，不是未经调查的需求热度排名。下表供本次评审取舍，不是全部批准开发。

| 层次 | 本次建议 | 理由与边界 |
| --- | --- | --- |
| 整体产品方向 | 覆盖科研、升学、实习、竞赛、交流、活动通知和资源 | 保留跨任务共性，不要求首版同步铺满内容 |
| 首个完整切片 | 有限来源的导师／科研发现、理解、比较及官方入口 | 首个试用任务明确、已有材料可用；包含本校与外部选项，不预先承诺国家或机构数量 |
| 切片内按需支撑 | 准备重点、适用资源、实际经历依据和待问事项 | 支持判断，不要求每条机会都有同样深度，也不承诺每个对象都有独立经历 |
| 轻量方案建议 | 私人收藏与选择理由 | 支持接续，但保存方式和真实返回收益仍待确定 |
| 共性结构检查 | 非科研比较样例与单次入口查询 | 防止把科研长流程强加给所有任务；不是同时上线另一套完整业务 |
| 首版非必需 | 推送、自动个人进度、跨设备同步、全平台采集、复杂管理后台 | 需求或维护依赖尚未清楚；维护可先由文件和人工完成 |
| 当前范围外 | 社区、公开黑红榜、申请代办、自动联系导师、完整教学训练与测评 | 不符合现行个人发现与选择定位；旧代码存在不构成保留理由 |

比赛兴趣与认定可以共存；综测须关联本人学校／院系、年度及适用规则。赛事奖项、学分和综测不能互换。未取得规则时不承诺加分，不为完整性提前开发计算器。

### 为什么推荐这个组合

| 可选方案 | 能解决什么／还剩什么 | 当前建议 |
| --- | --- | --- |
| 原站＋搜索／AI＋笔记 | 原办法可能足够，个人承担跨来源整理 | 保留为有效替代，不预设失败 |
| 入口导航 | 适合单次查询，深入判断仍需自行处理 | 作为轻任务的完整终点 |
| 精选资料库 | 支持发现与条件查阅，仅复述未必帮助选择 | 作为供给基础，不以条目数论价值 |
| 精选资料＋按需关联比较 | 支持具体工作、条件和经历依据的判断，但增加维护成本 | 推荐首版组合；深度随任务调整 |
| 全平台推荐与跟踪 | 依赖更广供给、个性化和持续更新，实际返回需求尚弱 | 暂缓 |

选择科研首例基于明确试用起点和材料准备程度，不是热度排名。优先目标是发现相关候选并理解足以决定是否继续的差异；准备、资源和记录服务该目标。没有可用经历时缩小可回答的问题、保留未知，不以官方摘要代替体验，也不扩大未经支持的承诺。这是待评审推荐，尚未得到同伴批准或效果验证。

### 7.1 推荐行为及可检查结果

下表沿用N编号；本次范围取舍优先于早期材料中的“核心候选”标签。验收为待执行要求，不是通过记录。

| 关联需求 | 推荐行为 | 可检查结果 |
| --- | --- | --- |
| N01–N02／P01 | 允许模糊兴趣浏览、明确对象检索和直接查资源；条件可选、可改 | 不填长问卷也可进入；无结果说明覆盖与放宽办法，不编造匹配项 |

| N12／全部内容 | 支持录入、关联、纠错与失效标记 | 关键结论有来源；更新后相关引用不继续展示已知错误；不要求先建后台 |

N10推送与N13自动进度不列首版必需。通知入口和适用规则解释仍可按任务保留。

### 7.2 两种任务深度

**导师／科研深入任务：**从兴趣或明确对象进入 → 找到候选及参与途径 → 理解研究工作和条件 → 按需比较实际经历依据 → 决定继续询问、去原站、保存、换方向或停止。准备和资源只在需要时插入，不要求完成所有步骤。

**入口轻任务：**说明要找的活动或资源 → 看到正确入口及必要适用说明 → 跳转或结束。不得强制先完成科研画像、候选比较或准备清单。

异常处理：无结果保留更换条件和原站路径；信息过期保留历史标识；来源冲突显示各自时间与适用对象；资格未知不直接判符合或不符合；资源不可用允许换路径；用户不参加不自动生成待办。

### 7.3 必要质量与使用约束

- 信息保留来源、适用时间及最近检查时间；先区分当前状态、历史样例与未知。AI整理不替代来源事实。
- 私人目标和笔记默认本人可见；不索取第三方账号密码。处理真实数据前确定存储、删除及外部AI传输范围。
- 不要求校园认证才能公开浏览；外部资源可以有自身认证要求。
- 检查键盘操作、清晰焦点、窄屏阅读、长文比较及链接辨识。数据规模未定前不编造性能承诺；开发计划须结合实际规模确定目标。
- 已确认UI约束：只用Primer React Product UI、Primer Primitives和Octicons；浅色中性、蓝色交互、系统无衬线、正常字距。不用Tailwind、自写CSS、内联style、sx或CSS-in-JS；不用emoji图标、eyebrow、副标题／口号、渐变、带边框内容卡和展示等宽字体。必要控件边框及焦点保留。旧HTML原型的视觉不能沿用。
- 先保证内容浏览、理解和入口可用；生成指导缺席或失败不能使已有信息不可读。人工整理、自动采集与AI生成的分工仍由后续设计决定。

## 8. 可行性、验收与待定事项

### 8.1 已知可行性与边界

公开来源已能提供部分人物、具体研究、项目条件和资源入口，可以制作有限样本。实际参与经历可得性不均，不能承诺全面评价；页面可读也不等于可以持续低成本维护。

小红书是候选信息渠道，不是首版默认依赖；不默认抓取私域群聊或绕过访问限制。优先选可维护来源，无法确认的重要状态保留未知或缩小承诺。

现有代码与原型包含旧社区方向和不符合当前UI规则的内容，资产需评估后复用。本稿没有证明运行环境、接口、持续集成或新功能已经验证。

### 8.2 三层验收

| 层次 | 何时判断 | 要看什么 |
