# 选导师指南：任务与信息结构设计

Last updated: 2026-10-03

状态：v0.3设计草案，按[需求分析v1.0](requirements-handoff.md)补入实际外部发现、结果整理与合并、失败后的继续方式、多主题私人记录隔离，以及仅发送用户明确选择的个人内容给外部AI；进一步明确查找中止与上限、错误合并修正和个人内容发送状态。依据[需求结论](needs-analysis.md)、[首版范围](requirements-handoff.md)与[四名候选试采](../constraints/mentor-source-reference.md)。本文把发现、理解和比较转为可实现的任务结构；页面划分、默认展示和交互仍为设计建议，尚未实现或经用户测试。P1效果与长期供给仍待验证。

## 1. 首版使用方式

学生可以带着模糊兴趣、明确导师或一个资源问题进入。先看到相关研究问题与候选，需要时打开详情、比较参与途径，最后去原站、保存个人理由或结束。浏览无需创建账号、填写画像或选择人生目标。

导航建议保留“找导师”“资源与入口”“我的探索”。每个探索主题保留自己的问题、候选和私人判断；用户可以先浏览，保存时再选择已有主题或创建主题。比较从结果或详情进入，不独立成为首页必走阶段。用户的参与目的可以改变；从本科科研切换到研究生申请时，保留已选人物，更新相应途径和条件，不改写其他主题的偏好。

| 起点 | 最短任务路径 | 什么结果就可以结束 |
| --- | --- | --- |
| 只知道喜欢AI或软件 | 浏览具体研究问题 → 看一项工作／人物 | 发现值得再了解的问题，或决定暂时不继续 |
| 已有姓名、方向或候选 | 检索已有资料／外部补查 → 详情或比较 → 查看适用途径 | 理解关键差异、未知与是否继续了解 |
| 已有明确入口或资源问题 | 资源与入口 → 必要适用说明 → 原站 | 找到落点；不要求先选导师或做准备 |
| 返回此前探索 | 我的探索 → 选择主题 → 候选、个人理由和信息变化 → 按需复看 | 恢复该主题的判断、修改或删除记录 |

本科科研、短期访问与研究生申请可并行关注。它们作为结果／详情中可选的比较视角，不设强制分流问卷；个人可能尚不知道最合适的参与方式。

## 2. 各处展示什么

### 发现与结果

使用一个检索入口，可输入姓名、机构、研究问题或关键词，先复用已有资料，并提供针对当前问题的外部搜索、正文读取与整理操作。用户能辨认当前查看的是已有资料、本次取得的信息，还是未完成的访问；搜索服务、自动触发条件与具体接口留技术试验选择，不宣称全网穷尽。旁边提供可选参与途径、机构／地区条件，全部可以清除。

每条结果优先显示：人物与机构、一句具体研究问题、相关作品入口、参与途径摘要、查看详情／加入比较／保存。与当前判断有关的未知紧邻条件显示，来源和检查日期可展开。匹配理由来自研究内容或明确条件，不显示综合适配分或“最佳导师”。

已有四条样本的默认顺序只是编辑顺序，不表示推荐或质量，也不是外部发现的覆盖上限。已有资料检索无结果时写“当前收录中未找到”，保留外部补查、修改条件和原站查找的办法；外部搜索无结果与搜索／读取失败分别说明，不写“没有这样的导师”。

**状态筛选建议：**兴趣探索保留招生状态未知者。若用户主动选择“有明确招募说明”，只纳入有本人／团队对应途径说明的条目，同时说明长期招募仍需确认年度名额；另提供查看未知条目的入口。不能仅因所属院系招生就标该导师开放，也不能用缺失字段做负分。

### 外部结果如何整理

每次补查围绕当前问题保留输入与本次范围，并把实际读到的相关信息整理成可查看的候选或依据：人物／团队、研究工作、参与途径与资源分别关联；说明与问题的联系、来源页面和原文依据。来源发布时间、适用时期与本次取得／检查时间分开；未知、历史状态、原文陈述与AI解释分别表达。只取得搜索摘要或链接而未读到相关正文时，保留为待查线索，不当作已确认事实。

结果不强制进入私人主题。用户可以直接查看、比较或结束，也可把候选及所用依据保存到选定主题；补查得到的公共资料按同一事实与来源结构复用，私人问题与理由不因此成为公共资料。

### 查找中止与运行上限

用户能中止正在进行的外部查找，保留原问题、已取得的信息、比较选择和已存主题记录。中止后停止后续搜索、读取、AI整理和自动重试，按工具能力尝试取消在途请求；迟到返回不继续自动写入该次已中止任务的候选或私人记录。已经发出的请求可能仍被外部服务处理，中止不等于撤回数据，涉及个人内容时按下文发送状态说明。

单次查找须有运行时间、来源／调用数量及适用费用额度的上限，具体阈值与可控制范围在技术试验中确定。达到上限后停止自动扩查与重试，说明停止原因及已完成范围，让用户继续使用部分结果、调整问题、主动发起后续查找或结束。不会因取消或达到上限清空已有资料，也不把部分完成显示成全范围完成；不要求用户每次先填写一份预算表。

### 与已有资料如何合并

合并先判断是否为同一人物／团队及同一事实、作品或参与途径，再决定复用、补充或保留待核。仅姓名相同不足以合并；机构、身份、作品和原文关系等依据不足时保持分开。demo可用文件流程处理待核项，不要求先建维护后台。

| 本次结果 | 整理与合并规则 |
| --- | --- |
| 再次读到同一来源中的相同信息 | 复用已有候选及依据，成功读取后记录本次检查时间；不重复新增候选或把它称为新人物 |
| 已有人物的新作品、新途径或补充条件 | 关联到对应人物，保留各自来源、适用对象与时期；不同途径保持独立 |
| 同一事项有多份来源 | 保留来源关系，补充能够支持的具体陈述；转载／转述不自动算独立佐证 |
| 条件、身份或招募状态互相冲突 | 保留各版本及其时间、对象和来源，标出待确认；不只因本次抓取更晚就覆盖旧值 |
| 新来源给出更正或当前状态 | 可更新有依据的公共事实并保留必要旧依据；已保存主题中的私人理由及所引用依据不被静默改写 |
| 身份或关联仍不明确 | 保留独立线索及待核原因，未经确认不去重、不强行关联 |

### 错误合并如何修正

发现同名人物或不同参与途径被误合并时，维护者能通过demo文件流程拆开公共记录，把各来源、作品、条件与途径关联回正确对象，保留必要的更正依据。修正不删除私人理由、待问项或旧引用，也不把一个主题的理由复制到另一主题。

原有主题记录的对象能够确认时修复其关联并让用户看见更正；无法判断一条私人记录原本指向哪位人物／哪条途径时，保留记录及原依据，标为关联待确认，由用户选择关联对象。不会自动把私人理由分配给所有拆出的对象，或擅自替用户改写理由。具体存储标识与修复方式留技术设计，不要求新增管理后台或完整版本系统。

修复公共关联不要求维护者查看私人理由原文；需要用户判断的关联在其私人主题中确认，不因纠错新增对私人笔记的访问权限。

### 访问失败时如何继续

| 情况 | 用户可继续做什么 | 信息与验收边界 |
| --- | --- | --- |
| 外部搜索失败或无结果 | 调整关键词／条件、主动重试、继续看已有资料或结束 | 失败与无结果分别说明；不据此推断不存在相关对象 |
| 一个来源正文无法读取 | 查看失败位置、打开原站、改查其他来源或稍后重试 | 该来源仍是待查线索；旧缓存注明取得时间，不写成这次已读取 |
| 多个来源仅部分成功 | 先看已成功取得的信息、比较或保存，再选择是否补查 | 成功依据可整理；未读到的条件保留未知，不要求全部来源成功才继续 |
| AI整理／解释失败 | 阅读已取得原文、已有资料和官方入口，或主动重试整理 | 不丢已取得资料和私人记录，不以生成文字填补读取失败 |
| 用户中止／查找达到上限 | 继续使用已完成结果，调整问题或主动发起后续查找 | 说明中止／限额原因和部分完成范围，停止自动扩查与重试；不会把中止写成无结果或删除已有信息 |

重试后按上表去重；保留原问题、已取得信息、比较选择和已保存记录。至少一次真实外部发现仍须成功读取相关正文并用于整理，失败记录不能替代该验收项；模拟故障只验证继续方式。

### 人物详情

默认先回答“研究什么”和“可以通过什么方式进一步了解”，再按需展开：

1. **研究问题与作品：**选少量能说明差异的工作，标明作者／团队关联；一项合作不能代表全部研究或确定日常指导人。
2. **参与途径：**本科科研、短访、硕博项目分别列出。每条显示关联依据、适用身份／时期、关键条件、当前可确认状态、原入口；不把全部条件堆在人物简介里。
3. **指导与实际经历：**先展示已取得且与问题有关的材料。团队承诺、参与者叙述、关系／去向记录与通用建议有不同名称；没有材料时说明当前能回答到哪层，按需看待问事项。
4. **准备与支持：**用户需要时说明准备重点及理由、相关资源入口。读论文、动手试做与联系均是可选路径，不生成统一能力差距表。

“去原站”“保存理由”“返回结果”一直可用。首次进入不用读完所有分节；看到一个合适入口后就可结束。

### 比较

原型先以两名候选检验可读性，属于测试配置，不是产品永久人数上限。比较按当前问题组织：研究问题、相关作品、所关心参与途径、关键条件、指导依据与未知。不同层次材料不可伪装成同一指标：本科进组与博士申请可以并列，但明确不同目的，不能计算高低。

用户可以只比较研究内容；需要时再选择参与目的。删去一个候选不会删除收藏；只剩一个时仍可阅读，零个时返回结果。窄屏按同一比较问题连续展示各候选，保留姓名，避免只能来回横向寻找；具体Primer布局留到原型验证。

### 资源、入口与探索主题

资源结果只需要用途、适用前提、费用／权限等关键限制及落点。例如需要算力时保留资源获取条件，未获批不能显示“已可使用”。入口查询完成后不自动创建准备任务。

“我的探索”按主题保留当前问题、偏好、人物、可选关联作品／途径、用户自己的理由和待问问题。同一候选可以进入多个主题；保存时明确当前目标主题。收藏不是申请计划或订阅。删除个人记录与取消比较分开；来源失效仍保留私人理由并说明信息状态。

私人理由和待问项归属于“某个主题中的某个候选记录”，不能存入多人共用的公共人物资料。修改主题A中的理由、取消候选或删除主题A，仅影响A的私人记录；主题B的记录和公共资料仍保留。切换主题时使用该主题的偏好和私人记录，公共检索／合并不会带入其他主题的理由。公共事实发生变化时说明变化，不替用户重新写理由；用户可以按新依据自行修改。

demo须在声明支持的设备／浏览器环境中保存多个主题，关闭页面重开后仍可恢复。会话状态可以用于前期操作试验，但不能代替此项验收。持久化技术、账号与同步方案留技术设计；删除主题的实际范围须说明，不默认承诺跨设备同步或外部服务中的删除。

### 个人内容与外部AI

个人问题、偏好、私人理由、笔记和待问事项，仅在用户明确选择后才能发送给外部AI。发送前能看见本次选中的具体内容／片段、接收服务和用途；用户可以取消选择或不发送，发送操作本身可确认这次选择，不要求重复确认。保存、浏览、切换主题和曾经发送某一条内容都不代表其他私人内容也可发送。

公开资料的AI整理与个人内容发送分开：仅选择主题A的一条理由时，请求只能附带这条选定理由及任务所需公共依据，不能自动携带A的其他笔记、主题B的内容或整份探索记录。关键词展开、摘要、比较、重试和历史上下文均遵守该边界，未选择内容不能经改写或摘要绕过选择；由个人内容生成的摘要仍按私人内容处理。AI输出涉及选定个人内容时保存在相应私人主题，不回填公共资料。取消选择后不再用于后续请求，也不自动续用包含该内容的外部会话上下文；本地删除不宣称外部服务已同步删除，外部保留与删除条件在选定服务后明确。未选中个人内容时仍可使用公共资料发现、浏览、比较、保存与原站入口。完整边界见[隐私说明](privacy.md)。

### 个人内容的发送状态

选择内容与实际发送分别显示。只有能够确认请求尚未发出时才显示“尚未发送”；已发出则显示“已发送，等待结果”，收到响应后显示结果或返回的错误。发生超时、断连或取消而无法确认送达时，明确显示“发送状态未确认，可能已发送”，不据此承诺内容未离开本产品或已被撤回。

用户中止任务或取消内容选择，会阻止后续请求附带该内容，并按工具能力停止等待；已发出的内容仍按接收服务的实际规则处理。主动重试前能查看这次仍选中的内容、接收服务和前次状态，重试不自动扩大个人内容范围，也不因未收到结果而无限重发。

## 3. 内容关系与最少信息

这是概念结构，不指定数据库或API。每一事实可关联多个来源；检查时间、来源发布时间和适用年份分别保存。

| 对象 | 最少需要什么 | 关系和关键约束 |
| --- | --- | --- |
| 人物／团队 | 稳定标识、姓名、机构、身份来源 | 同名不能自动合并；可以关联多项工作和途径 |
| 研究工作 | 问题、方法简述、原作品、人物关联依据 | 事实与编辑解释分开；项目要求不自动变成招生门槛 |
| 参与途径 | 类型、人物／机构关系、适用身份和时期、条件、状态、入口 | 人物明确招募、院系入口、制度上的待核路径分开；各条独立更新 |
| 条件／陈述 | 适用对象、要求性质、来源、检查时间、已知／未知／争议 | 学校建议不覆盖院系硬要求；不通过空值推断符合或不符合 |
| 经历／记录 | 叙述者或发布者角色、团队、时期、原文出处、可支持的判断 | 转述不能算独立佐证，校友去向不能代表指导质量 |
| 资源／办理入口 | 用途、关键前提、链接、状态 | 可独立查询，也可关联途径或准备需要 |
| 探索主题 | 主题标识、当前问题、可修改偏好 | 与公共资料分开；多个主题分别恢复，不自动混合偏好 |
| 私人候选记录 | 所属主题、保存对象、个人理由、可选待问事项、引用依据与时期 | 同一公共候选可有多份主题记录；修改／删除一份不影响另一份，不由源页面失效自动删除 |
| 一次外部查找 | 输入问题、本次范围、成功来源、失败／待查线索、取得时间、运行／中止／限额状态 | 区分本次读取与已有资料复用；保留部分结果，中止后不自动继续写入；原始个人输入不因整理成为公共内容 |
| 一次个人内容发送选择 | 本次选定内容／片段、接收服务、用途与所属主题、已知发送／返回状态 | 仅组装明确选择的个人内容；取消后不用于后续请求；无法确认送达时保留未知，不要求永久保留发送副本 |

状态由不同问题组成，不能只用一个“已验证”标签：**关系是否成立、来源是否可读、适用时期是否明确、是否有当前招募、是否知道个人资格**分别判断。界面只呈现影响当前任务的部分，编辑侧保留完整依据。

## 4. 用现有样稿进行案头检查

检查日期2026-09-30；材料沿用9月29日试采及9月26日已读作品，没有为此重新核对招生时效。下面是作者按方案检查内容和逻辑，不是用户操作、可用性测试或实现验收。

| 任务与材料 | 按本方案能形成的判断 | 暴露的缺口／原型必须检查 |
| --- | --- | --- |
| 模糊AI／软件兴趣，比较王翔与熊英飞 | 可区分模型知识编辑与程序正确性分析；都可只读问题继续探索 | “自然语言程序状态”等解释是否容易理解尚未观察，不能据作者能区分就认定用户能懂 |
| 比较Chen与Zhang，并切换到本科科研视角 | Chen校内机会明确限CMU学生；Zhang短访只有制度入口、个人接收未知 | 必须保留原研究兴趣，不能把不适用一条途径显示成“此导师不适合你” |
| 明确想找可联系的本科科研导师 | 王翔有长期欢迎文字；Chen有身份限定；其余缺本人相应说明 | 招募说明、当前名额和个人资格不能合并；四条样本不是完整搜索结果 |
| 查看Zhang培养体验 | 可以呈现一位校友的关系／去向记录，日常指导仍未知 | 验证用户是否误把去向当质量背书；待问清单不能填充成体验结论 |
| 只查询HKUST研究生入口或算力资源 | 入口／资源可以直接结束，不要求选定导师、补课或收藏 | 官方项目具体适用性仍按原站确认；资源实际权限未取得 |
| 返回候选，遇到来源失效（模拟异常） | 设计要求保留私人理由并单独提示源状态 | 尚无持久化实现；需在原型加入明确模拟，不冒充真实内容更新 |

本轮设计可表达上述分支，尤其能避免把个人名额、机构招生和短访制度混成一种机会。未解决材料薄弱的问题：熊英飞参与途径、具名导师短访接收、四人的实际指导经历和维护能力仍留在对应供给待办。

## 5. 原型任务与判断标准

沿用N01—N09、N11—N12及既有H/V定义，不新增一套验证关卡。以下在9月30日固定样稿检查的基础上，补入实际外部发现、合并、失败继续、多主题持久隔离和个人内容发送检查；均为待执行标准，不表示已验收。固定样稿只能支持部分检查，至少一次实际外部发现须使用真实搜索与正文读取；验收以需求主稿第8节为准。

| 原型任务 | 关联需求 | 可检查结果 |
| --- | --- | --- |
| 不填目标浏览并打开一个研究问题 | N01—N04 | 能进入、看到问题与作品出处、返回或结束；无强制画像 |
| 选择两人比较，改变参与目的 | N02、N05 | 人物保留，途径条件随视角变化；未知不被判不符合，来源可回查 |
| 从本人招募、院系入口、待核路径中找可确认结论 | N04、N08 | 三种关联有清晰区别，历史／长期说明不当当前名额；发现误解则改标签或解释 |
| 查看经历依据并只保留一个待问问题 | N11 | 能分清公开记录与体验未知；无人格分，无强制提问 |
| 直接找到资源或项目入口 | N06—N08 | 不强制比较和准备；访问限制可见，跳转即完成 |
| 保存／修改／删除理由；检查异常 | N09、N12 | 在明确告知的存储范围内行为一致；来源失效不删私人记录，维护修改不静默改变用户原理由 |
| 针对输入补查一个相关外部来源，再查已有来源 | N02—N04、N08、N12 | 正文中的具体信息与问题关联，显示来源和时间；已有对象复用，新事实补充；重复读取不新增重复候选，冲突及身份不明保留待核 |
| 让一个来源失败后继续，随后主动重试 | N02、N08、N12 | 成功信息、比较选择及已存记录可用；失败、缓存与本次读取可区分；重试去重，失败不当新发现通过 |
| 把同一候选加入两个主题，分别写理由并关闭页面重开 | N09 | 两主题均恢复；修改／删除A的记录不改变B或公共资料；公共资料更正不静默改写已保存理由 |
| 只选择A的一条理由发送给外部AI，再取消选择 | N09及个人数据约束 | 用合成私人内容检查实际请求，只含选中个人内容及公共依据，不带其他笔记／B内容；输出保持私有，取消后后续请求不再附带；未选择时普通浏览和保存仍可用 |
| 查找取得部分结果后中止，再触发一次运行上限 | N02、N09及运行约束 | 已取得结果、比较选择和已存记录保留，后续调用／自动重试停止，迟到返回不继续自动写入；原因及完成范围可见，具体阈值按试验声明 |
| 用合成对象模拟同名人物／不同途径误合并并修正 | N03、N09、N12 | 公共来源与途径回到正确对象；私人理由、待问项和原引用保留；无法确定原关联时由用户确认，不自动复制理由到所有拆出对象 |
| 用合成个人内容检查未发出、等待、返回、超时／断连与中止 | 个人数据与异常约束 | 状态符合实际证据；送达不明时显示可能已发送，不误报未发送或撤回；重试只携带当前明确选择内容，中止／取消后不继续发送 |

真人试用问题保持中性，如“你现在知道了什么，仍有什么不能判断？”“接下来你想做什么，也可以不继续？”不要求选出评审者偏好的导师。记录关键误读、是否需要他人解释及自主结束位置；任务用时仅辅助。若同一任务在原站加笔记已足够，应减少重复内容，不能只以做出了页面证明增量。

## 6. 实现前需要决定的少数事项

- 持久化技术与删除方式：支持已采用的多主题重开与隔离，声明设备／浏览器范围；原型会话状态不替代demo验收。
- 搜索／正文读取与合并流程：选定能实际运行的工具，核对关联、去重、冲突与误合并修正；确定单次时间、来源／调用及适用费用上限和中止方式，验证部分结果保留。
- 外部AI服务及请求组装方式：落实仅发送用户明确选择的个人内容，核对接收服务、用途、保留与删除条件；验证发送状态、送达不明和中止／重试行为，其他主题内容不会被自动附带。
- 本批demo来源、必要核对与改错方式：内容准备时明确。长期维护负责人及周期在决定持续服务时安排，不是demo前提。
- Primer现有组件如何承载结果列表、两人比较和窄屏阅读：实际实现时确认API与键盘行为，遵守[UI规范](ui-system.md)，不新增手写样式例外。

实施时把“真实外部来源读取与整理／合并”和“两个主题的保存／隔离”分别落实为可验证部分，再接入详情比较、资源直达、个人内容选择发送与失败继续；具体分工、页面和存储方案在技术设计中决定。导航和视觉验证使用同一Primer体系；研究材料缺项继续显示未知，必要时缩小展示承诺。

随后按主稿8.2做一次完整演示走查：真实外部查找与正文读取 → 整理并合并已有资料 → 比较两个候选 → 分别保存到两个主题 → 关闭页面重开 → 检查失败／中止后的继续、误合并修正与个人内容选择发送。后面的故障、误合并和个人内容检查可用明确标注的模拟／合成输入；记录实际来源、人工补位和未完成项，不把模拟成功当作真实外部发现或用户收益。
