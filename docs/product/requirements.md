# 需求基线与分析契约 v1.0

Last updated: 2026-10-03

本文件是[需求分析 v1.0](requirements-handoff.md)的详细编号与分析契约附件，与主稿共同维护。已采纳指产品需求，不表示已实现或实际收益已验证。后续设计不能因历史候选、已有代码或旧原型自动扩大范围。

## 1. 八部分分析契约

需求分析解释为什么做、为谁做、已有办法和具体问题，再推导价值、范围、行为与验收。当前主稿已按以下八部分整理，具体证据见[论证记录](needs-analysis.md)。

| 部分 | 必须回答的问题 | 应交付内容 |
| --- | --- | --- |
| 问题背景 | 学生面对怎样的环境，为什么值得研究？ | 具体案例／数据及适用范围；不能从信息分散直接推出需要新平台 |
| 产品对象 | 哪些人、在什么阶段和条件下、想完成什么？ | 跨学科、阶段、目标与限制的用户任务分组；整体对象与 AIDS 首例分开 |
| 现有解决方式 | 用户现在如何处理，已有工具能做什么？ | 学校平台、搜索、群聊／公众号、招聘平台、通用 AI 等同任务对照；优势、限制与可复用部分 |
| 具体问题与需求 | 在哪一步受阻、原因和后果是什么、期望什么结果？ | 情境—任务—现有做法—障碍—期望结果；区分事实、推断和未知，说明问题重要性的依据 |
| 产品价值与定位 | 产品能改善哪部分，为什么值得额外使用？ | 从未满足需求推导的价值主张、差异与能力边界；允许结论是现有办法已足够 |
| 范围与优先级 | 整体覆盖什么，首版先做什么，为什么？ | 整体需求地图及首版必需／可选／暂缓建议；不能用首个案例缩小全产品调研 |
| 功能与使用要求 | 为满足需求，系统应有什么行为和约束？ | 可追溯功能、关键流程、易用性、信息时效和个人数据要求；不提前定全部实现细节 |
| 可行性与验收 | 信息能否获得和持续维护，如何判断有用？ | 供给与责任、成本和限制、可观察结果、验证计划及未决假设 |


完成标准：八部分有明确结论、依据或有理由的后续未知；需求、方案与效果分别判断；取舍和可检查结果可以交接。页面数量、收录数量及模型解释流畅不能代替需求分析。已有可比人群证据直接采用，无需先重复本校问卷。

## 2. 当前范围与采用状态

首个交付为选导师指南demo，覆盖校内外、研究所及海外的探索能力；具体资料范围随演示任务和可获取来源确定。整体研究保留其他机会类型，当前不同时实现。

- N01–N05、N08：核心发现、理解比较和入口；包含实际外部搜索、读取与整理。
- N06–N07：按需准备与资源，可独立查找和结束。
- N09：多个持久探索主题已采纳，保留候选、依据和私人判断，具体存储留设计。
- N11：实际情况考察已采纳，经历及知情者入口按来源条件提供。
- N12：基本供给与改错；自动化主整理、团队关键核对，具体工具留设计。
- N10、N13：推送和自动进度保留编号，当前非必需。

长期维护、全量实时状态、完整聊天、跨设备同步及复杂后台不列demo必需。社区是可选未来扩展，无预设阶段。准备不扩展为知识教学或练习测评。

## 4. 使用、信息与质量约束

- 从当前问题进入，允许模糊兴趣、修改条件、换方向、暂停或拒绝；简单入口查询不必走完整流程。
- 人物、研究工作、参与途径、适用条件、来源及个人判断分开。研究方向不代表招生，机构有项目不代表某导师接受。
- 原文支持的硬性要求、优先项、建议、历史状态和未知分别表达。历史材料可用于发现；不能当作当前开放机会。
- 个人主题保留候选、来源、理由和待问项；公共资料可复用，主题偏好和私人笔记不自动混合或公开。
- 外部结果保留具体正文依据、与问题的联系、来源和时间；已有对象复用，新事实按作品／途径关联；同名、冲突或身份不明不强行合并，重试不重复新增候选。
- 查找可中止，单次运行时间、来源／调用数量及适用费用额度有上限，阈值和可控范围在技术试验明确。中止／达到上限保留部分结果、比较选择及已存记录，停止后续调用和自动重试；迟到返回不继续自动写入已中止任务。
- 准备只提供重点、理由和可选路径；资源说明用途及最少获取前提。浏览或收藏不自动生成任务和订阅。
- 仅向外部AI发送用户明确选择的个人内容；发送前可查看选中内容／片段、服务与用途，可取消或不发送。未选中笔记、其他主题及整份记录不自动附带，涉及个人内容的输出保持私有；取消后不用于后续请求。真实个人数据进入前明确存储、删除及所选服务保留条件，本地删除不宣称外部已同步删除，详见[隐私边界](privacy.md)。不收集第三方账号密码；外部办理回原平台。
- 个人内容的选择与实际发送分开，说明确认未发送、等待结果、已返回或送达不明；超时／断连／取消不证明未发送，不宣称已撤回。重试前可查看当前选择和前次状态，不自动扩大范围或无限重发。
- 无结果、网络失败、来源冲突、资源不可用和AI失败均有可理解结果；保留原问题、成功信息、比较选择和已存记录，允许改查来源、主动重试、原站查看或结束；缓存与新获取区分，失败与未读取线索不算实际外部发现通过。
- UI遵循[Primer规范](ui-system.md)，检查键盘、焦点、窄屏、长文比较及链接辨识；实际性能和部署目标在技术设计中确定。

## 5. 验收与后续验证

统一使用[主稿第8节](requirements-handoff.md)的demo任务与成果标准，不另建第二套通关清单。至少一次实际外部发现、真实对象比较、多主题重开和轻任务直达是交付检查；经历内容按实际可得性呈现。没有完成的能力如实记录，不能以模拟或固定样本替代实际外部发现。

H1–H6/V1–V5定义保留在[论证记录第8节](needs-analysis.md)，分别支撑发现、判断、体验、帮助、接续及持续供给的针对性验证。作者走查、学生试用、真实返回和长期运营分别报告；长期更新计时及维护预算仅在决定持续服务时安排。

## 6. 变更规则

需求调整须说明对应问题、现有办法、预期帮助和范围影响；同步主稿、概览及里程碑。模型、搜索接口、存储与页面设计属于实现选择，不必重新询问已确认的多主题、个人使用或外部发现方向。涉及新的费用、私人数据边界或明显体验取舍时，提供具体方案协商。
