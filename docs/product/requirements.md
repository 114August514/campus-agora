# 个人机会发现与行动支持：需求基线草案

Last updated: 2026-09-27

状态：P1 收敛稿，可用于内容原型与任务观察；不是已确认的完整开发范围。产品定位以[概览](overview.md)为准，执行阶段见[里程碑](milestones.md)。本文将已有研究转为可讨论、可验收的需求，不新增用户调查结果。

## 需求分析必须交付什么（2026-09-24）

用户明确：先回答为什么做、为谁做、解决什么问题和现有办法哪里不足，再推导功能、范围及验收。本文现有 N01–N13、准备卡与原型属于候选方案，不能代替完整需求分析；八部分论证现已整理为[需求分析初稿](needs-analysis.md)，实际收益与供给验证仍未完成。

完整需求分析报告必须包含以下八部分，可在现有文档基础上整理，避免重复调研或堆叠文件：

| 部分 | 必须回答的问题 | 应交付内容 |
| --- | --- | --- |
| 问题背景 | 学生面对怎样的环境，为什么值得研究？ | 具体案例／数据及适用范围；不能从信息分散直接推出需要新平台 |
| 产品对象 | 哪些人、在什么阶段和条件下、想完成什么？ | 跨学科、阶段、目标与限制的用户任务分组；整体对象与 AIDS 首例分开 |
| 现有解决方式 | 用户现在如何处理，已有工具能做什么？ | 学校平台、搜索、群聊／公众号、招聘平台、通用 AI 等同任务对照；优势、限制与可复用部分 |
| 具体问题与需求 | 在哪一步受阻、原因和后果是什么、期望什么结果？ | 情境—任务—现有做法—障碍—期望结果；区分事实、推断和未知，说明问题重要性的依据 |
| 产品价值与定位 | 产品能改善哪部分，为什么值得额外使用？ | 从未满足需求推导的价值主张、差异与能力边界；允许结论是现有办法已足够 |
| 范围与优先级 | 整体覆盖什么，首版先做什么，为什么？ | 整体需求地图及首版必需／可选／暂缓建议；不能用首个案例缩小全产品调研 |
| 功能与使用要求 | 为满足需求，系统应有什么行为和约束？ | 可追溯功能、关键流程、易用性、信息时效和个人数据要求；不提前定全部实现细节 |
| 可行性与验收 | 信息能否获得和持续维护，如何判断有用？ | 供给与责任、成本和限制、可观察结果、验证计划及未决假设 |

完成标准：八部分均有明确结论或有理由的待验证项；关键结论能追溯到来源或真实任务材料；候选功能能说明对应哪个用户问题；现有替代、供给约束和首版取舍没有被省略。不能用收集条数、原型完成、模型解释流畅或作者自己复走替代完成标准。无需把所有假设都证明后才允许原型验证，但不得把待验证收益写成已证实。

需求描述用户要取得的结果，功能只是解决方案。例如“理解导师研究任务的差异”是需求，“代表作品关联、比较页和准备卡”是候选方案；“缺资源”应先查现有资源如何取得，再决定是否增加资源检索功能。

当前顺序：先把已有证据归入上述结构，补齐问题背景、对象分层、现有办法同任务对照、问题原因与重要性以及价值论证；仅对影响结论的缺口补调研。原型与用户观察用于检验关键假设，Primer 迁移保留为后续工作，不因原型已经存在而抢先成为主任务。具体实际观察遵守[需求分析的验证约束](needs-analysis.md)，问卷不是固定前置步骤。

2026-09-27证据采用规则：以[需求分析文首结论](needs-analysis.md)作为当前评审基线。已有证据在适用范围内直接采用，未测群体比例或效果不妨碍需求取舍与有限设计。N01—N08、N11及基本维护N12构成推荐方案中的核心／按需能力；N09轻量记录作为方案建议保留，N10推送及N13自动进度暂不列首版必需。普通入口和认定说明仍按相关任务保留。H/V不是全部通过后才能推进的串行关卡；新增验证必须说明会改变哪项决定。

## 1. 已确认边界与本轮建议

已确认：个人可以独立使用，连接机会、准备方法与资源支持；覆盖不同学科、阶段、机构和目标；AIDS 导师探索是首个深入案例。办理跳转官方入口，社区不是当前范围。

本轮建议：首个内容原型以导师案例深入验证发现与选择，按任务需要组合比较、准备、资源和私人记录；同时以轻量兴趣与入口直达任务检查是否强加步骤。直接到达入口或了解后离开也可完成任务。范围分层以[需求分析第6节](needs-analysis.md)为准，首个原型内容不等于产品长期边界。

暂不决定：所有机会类型同时上线、通知是否进入首版、指导生成方式、账号与跨设备方案、覆盖规模及更新承诺。以下“核心候选”表示优先验证，不代表已批准开发。

## 2. 用户任务及优先验证理由

背景与目标用户统一以[需求分析第1—2节](needs-analysis.md)为基线：整体服务对象、信息范围、首个案例及首版优先用户分别记录。下表是任务需求，不是已验证人群占比或新增用户端范围。

| 用户任务 | 触发情境 | 希望取得的结果 | 目前依据与缺口 |
| --- | --- | --- | --- |
| 探索可能性 | 方向不明确，不知道可以做什么 | 找到愿意继续了解的任务与机会 | 用户诉求、G1/G11；真实探索过程未观察 |
| 找到并比较选择 | 已有兴趣、时间或地域限制 | 解释候选差别，形成自己的选择理由 | G2/G3、R2/R3/R5；相对搜索与表格的收益待测 |
| 判断准备重点 | 看见机会，但不了解日常任务或所需能力 | 区分基本要求、优先条件与可选准备，开始一个具体行动 | G8–G10、三张准备卡；指导深度待测 |
| 获得行动资源 | 缺算力、文献、设备、指导或经费 | 找到相关入口并明确获取前提 | G12、官方资源试采；个人权限与实际获取未验证 |
| 持续推进 | 离开后回来，或目标／信息改变 | 保留已有理解，调整而无需重新整理 | G5/G6、R5/R8；返回频率和提醒价值未测 |
| 完成已经在读的要求 | 培养方案里有跨学年必修，合格活动分散且类别受限 | 知道这场算不算、还差多少、何时提交、交到哪里 | 形势与政策公开规则；真实选听、登录清单和提交未观察 |

[学生发展文献调研](../constraints/student-development-literature.md)进一步提示：年级仅作可选上下文，不按年级锁定实习、竞赛或升学；保留学业支持的发现、选择与获取需求，不默认等同机会准备；具体课程教学、练习与学习效果验证已退出当前工作。本轮不据文献直接新增已批准功能。

用户状态与参与动机可以重叠、改变，不按专业、年级或竞赛类型推断兴趣。兴趣娱乐、共同参与、认定与发展目的均可决定比较重点；不强制动机问卷或固定标签。认定按具体用途与适用规则说明，赛事奖品、综测与学分／GPA不互相替代。同一候选支持同时比较兴趣体验与认定条件；认定不是赛事通用标签，须关联学校／院系、身份、年度或届别，原文需要时细化到专业、班级及转入情况。旧版或配套名单缺失保留待确认，不自动推断可加分或不可加分；用途不同的文件不自行互相覆盖。研究、就业、文化体验与个人兴趣均可成为目标。当前优先级基于完整任务所需能力及已确认诉求，不是已测得的需求规模或痛点排名。

暂缓默认建设：全自动适配评分、完整个性化课程体系、代办申请、自动联系导师、全平台社交内容爬取。社区属于范围之外的潜在扩展，不是排队等待开发的任务。

## 4. 完整路径与异常情况

本表列出可组合的能力，不是所有用户必须依次完成的流程。2026-09-26偏向复核见[需求分析第7节](needs-analysis.md)：单次入口、模糊探索和兴趣浏览可独立完成；N06准备产出只在用户确需准备时适用，N09保存与N10提醒不能由科研首例推广为全部任务的必要步骤。

| 步骤 | 用户操作 | 产品输出 | 无法顺利继续时 |
| --- | --- | --- | --- |
| 进入 | 选择探索、找机会／对象或找资源 | 可浏览内容与少量可选条件 | 不用长问卷拦住浏览 |
| 发现 | 搜索、修改条件、打开候选 | 相关内容、来源及覆盖说明 | 无结果显示放宽条件或继续查原站的办法，不编造候选 |
| 理解比较 | 看任务和条件，保存理由 | 候选差异与未知项 | 来源冲突说明冲突；不替用户补造资格或评分 |
| 准备 | 了解准备重点、选择探索方式或直接跳过 | 准备重点、理由及适用参考／资源入口 | 任务超出基础时可缩小一步或换方向；不计入或硬性条件已使参与不可行时停止；即使符合条件也可暂缓或不参与，不追加准备 |
| 获取资源 | 检查前提并进入资源平台 | 用途、资格、费用性质、状态、入口 | 无权限或资源未开放时明确待确认点，保留其他路径 |
| 参与 | 前往官方平台 | 正确入口及必要节点 | 过期时保留参考价值并查找新届信息；找不到就说明 |
| 返回 | 继续比较，修改目标或记录结果 | 保存的理由与下一步 | 源页面消失不丢个人记录；不假设能自动获知外部申请结果 |

可从任何适用步骤进入，不要求用户依次完成所有环节。资源是可独立发现的对象，不只附属于机会详情。

## 5. 内容与使用约束

- 人物／机构、作品、机会、指导、资源、个人记录分别表达；学位项目与导师的招生信息分别确认。此为内容概念，不是数据库设计。
- 公共内容保留出处、适用时期、最近检查时间和未知字段。有效期由来源决定，不设置一个适用于所有内容的更新周期。
- 个人目标、比较笔记和准备结果默认仅本人可见；不向其他学生展示。具体保存、删除、跨设备及 AI 数据使用方式在处理真实个人数据前确定，并同步更新隐私文档。
- 原型同时检查窄屏阅读、长文本比较、键盘操作及链接辨识。正式性能目标在样本量和访问场景确定后给出，不虚构响应指标。
- 公开浏览不以校园认证为前提；官方资源可能需其自身身份验证。产品不收集第三方账号密码，办理回原平台。
- 信息整理可先人工精选；AI 起草与自动采集需分别验证提取效果、专业解释和维护负担，不预设全部自动化。

### 自主选择与信息负担

遵守[概览中的帮助与资源原则](overview.md)：产品帮助处理当前问题，不给学生安排统一的发展任务。候选需求的“核心／重要”是团队验证优先级，不是告诉每位学生每件事都重要。

- 查看、收藏、未完成准备不产生催办、落后标签或默认任务；用户可以只了解、不参与，不必填写退出理由。
- 先说明与当前问题有关的内容，更多路径和准备按需展开；不默认呈现长篇能力欠缺清单，不以“你还差很多”引导追加学习。
- 文案写“若想尝试，可先了解……”而非“大二必须完成……”。资格要求与官方义务据来源准确表达，可选建议明确可选。
- 若未来采纳提醒，不自动订阅全部推荐、不因用户不行动反复催促；准确日期可展示，不人为添加紧迫感。

验证除原有停止案例外，再加入“资格符合且仍可参加，但用户只想了解／暂不参加”的情境：检查能否自然结束、是否被自动追加任务或提醒、是否把建议误读成必做要求。记录哪些内容让参与者感到选择更清楚或负担增加，用于修改内容和交互；不能据少量反馈宣称临床或普遍的减压效果。

### 资源适配与替代

遵守[产品侧重点与内容深度](overview.md)：发现、理解与比较是核心，准备指导和资源连接提供支持。N05–N07 说明准备重点、理由、可选路径及适用支持，不要求逐知识点教学。

资源默认说明用途、适用条件、必要投入和获取入口；条件未知时保留未知。学校与外部来源均需判断适配，学校已有不等于最优；不适合时可解释差异、提供替代。资源可以独立查找。章节或示例链接仅在解决当前选择问题确有必要时补充，不作为每条资源的必需粒度，也不默认制作练习与反馈。

V3 检查能否理解资源用途与获取条件、识别不匹配并选择替代或停止；不开展 Python 等具体知识的学习效果测验。区分公开可读与获准使用，不合并未经确认的课程关系。此前章节走查仅作为[失配旁证](../constraints/student-development-literature.md)，其中教学对照计划退出当前任务。

## 6. 内容供给验证

先沿首个导师案例完成相互关联的人物、作品、机会／参与入口、准备和资源样本；另用职业探索和竞赛检验是否过度依赖科研结构。缺少招募信息时保留缺口，不为凑齐流程创造机会。

每条样本记录来源、可提取字段、缺口、关联判断、整理时间、复核时间及更新触发；单次计时与后续更新分开。先验证来源可用性和关键关系，再选择值得自动化的来源。额外收集数量必须服务于明确问题，20–30 条导师样本是可调预算，不是阶段完成门槛。

区分三种支持：原站已有指导作为候选，适合当前任务时可直接关联；公开事实可提取整理；跨来源解释和新准备建议需要人工判断。若少数维护者无法承担某类深度指导，就降低内容深度或覆盖范围，并保留原站入口。

2026-09-24 的两把密钥设想见概览，尚未采纳。V5 仍先计人工时间和纠错负担。在该设想被单独接受之前，不实现抓取、小红书采集、群机器人或按使用者密钥生成指导。

2026-09-26来源复核补充：N03/N08须区分持续开放与最小提前量，以及同机构不同参与路径的入口／资助条件；不把可选科研经历变成必须补齐的准备项。N12将本地摘要补全、真实源规则变化与模拟更新分别记录。已执行两条AI辅助复核，仅说明工作构成，尚不足以估计人工成本，详见[需求分析第8节](needs-analysis.md)。
