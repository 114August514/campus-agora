# AIDS 学生导师探索：首批具体调研

Last updated: 2026-09-26

范围说明：本文仅为首个 AIDS 导师探索案例的研究，不是全产品用户边界或完整需求结论。整体调研范围以[产品概览](../product/overview.md)为准。

## 范围与结论

用户选择以 AIDS 同学的需求跑通首个案例；个人偏研究，对 AI、软件等感兴趣，暂不偏好 AI4S 和 AI for Math。产品同时支持偏就业的同学。此偏好不是所有 AIDS 学生的共同偏好，也不代表排除研究中使用数学。

本次完成公开网页桌面调研和十名人物的方向初筛，尚未完成招生项目、目标入学年份、近期论文逐篇分析和实验室实际体验核验。下表是方向探索入口，不是录取推荐、当前有名额清单或导师品质背书。P1 仍在进行中。

产品价值应是：帮助个人回答“我想研究什么 → 哪些老师正在做 → 日常研究和培养方式是否适合 → 如何进一步了解和申请”。先做个人候选比较，不以社区活跃为前提。

## 从研究日常探索方向

以下分类是本项目的探索建议，方向可交叉，不是院系分类或就业保证。

| 探索线 | 具体问题示例 | 常见工作与适配线索 | 低成本试做建议 |
| --- | --- | --- | --- |
| AI＋软件工程 | 编程智能体怎样理解仓库、修复错误、生成有效测试 | 阅读代码、设计工具和评测、分析失败；喜欢构建系统又愿意验证方法 | 选小型开源项目的历史已修复问题，比较模型修复结果与原测试、补充测试；留意信息泄漏 |
| AI 系统 | 如何降低推理延迟、显存或训练成本 | 性能测量、编译与运行时、分布式和底层调试；部分项目很偏硬件 | 同一设备、模型和输入下比较推理配置，记录延迟、吞吐与质量，而非只追单个速度数字 |
| 通用模型／智能体 | 推理、记忆、对齐、检索与工具使用如何改善 | 读论文、设计对照、训练或评测、误差分析 | 选一个开放评测子集比较两种检索或工具使用方案，整理失败类型 |
| 软件工程／程序语言／安全 | 如何发现缺陷、分析程序、验证或保护软件 | 程序分析、形式化推理、测试与系统实现；不一定使用大模型 | 跑一个静态分析或模糊测试工具，复现一类缺陷并分析误报 |

上述试做是进一步探索时的可选办法，不是方向筛选的必经步骤或固定时长要求。可以先读具体问题与工作例子，判断是否想继续了解；决定动手后再按基础和资源安排。试做不替代完整科研经历，也不能据此判断能力上限。

偏研究者更关心问题空间、方法训练、导师反馈和独立性；偏就业者另看工程训练、实习安排及公开毕业去向。两者都关心培养质量，不能把硕士等同就业、博士等同某种固定去向。

## 信息在哪：不只小红书

| 渠道 | 提供什么价值 | 首批收集方式 |
| --- | --- | --- |
| 院系／研究生院／研究所招生页 | 项目、学位、资格、年份、正式截止日期 | 优先选稳定来源；导师卡关联项目通知 |
| 教师个人站、实验室站 | 研究问题、近期项目、组员、招生入口 | 公开页面定向采集；保留原链接和查看日期 |
| 小红书、公众号、X 等本人账号 | 新招募、组内介绍、非正式预告 | 首期支持保存链接和用户提供的正文／图片，再定位本人或正式入口；不承诺全平台覆盖 |
| 实验室知识库、GitHub | 组内公开说明、代码和实际项目 | 从本人主页出发找链接，优先读取项目与公开说明 |
| 学术元数据与论文 | 近期研究变化、合作者和项目线索 | 使用提供的 API／开放数据，再返回论文和主页核实 |
| 学生／校友个人页及经验帖 | 学生实际做什么、经历与去向 | 私人比较的补充线索；需标注年份与观察范围 |

可核查的跨平台实例：[卞亚涛团队招生 PDF](https://yataobian.com/docs/Recruitment-chs.pdf)列出小红书、公众号与 X；这里仅用于证明渠道存在，其 AI4SCI 等主题不是用户偏好的推荐方向。[姜伟雄个人站](https://jiangwx.github.io/)也指向小红书与飞书组内知识库。这些实例不能证明“大多数老师用小红书招生”。

信息分散的产品机会在于把“社交平台上看到的招募”连回“是谁、研究什么、属于哪个项目、下一步怎么做”，而不只是复制通知。广告式自述也不能直接证明培养体验。

## 如何看懂一个导师的方向

1. 从机构主页确认身份和当前单位，再找本人维护的网站、实验室和论文入口；同名作者不能只凭姓名合并。
2. 选近两至三年三至五项相关工作，分别写清研究问题、方法、应用对象、产出。数量是阅读预算，不是质量分数。
3. 区分导师长期方向、学生具体课题、一次合作，以及现在希望招人的课题。共同署名不自动表示负责日常指导。
4. 每条解释能回到论文、项目或本人表述。AI 可以辅助翻译与概括；只读标题不足以形成可信的方向判断。
5. 输出学生能理解的描述，例如“让编程智能体找到跨文件的数据流”，而不是只堆 LLM、Agent、AI 等标签。

“数学推理能力”“数学证明研究”和“AI for Math”可能交叉，需看问题目标；程序验证含数学也不自动成为低优先级。混合实验室按项目标记适配与不适配，保留用户选择。

## 导师与实验室比较：具体到培养体验

学术方向通常能从公开资料建立初步认识；日常指导和对待学生的方式往往需要进一步了解。产品不忽略后者，也不把缺少公开信息解释为差。

| 维度 | 先能看什么 | 后续应确认的具体问题 |
| --- | --- | --- |
| 日常指导 | 组规模、共同指导说明、公开培养材料 | 实际跟谁做？多久得到一次具体反馈？老师忙时谁指导？ |
| 课题自由与支持 | 学生项目、公开研究计划 | 能否换题？连续几个月没结果通常怎样处理？ |
| 毕业与资源 | 培养规定、招生说明、公开资助 | 实际毕业要求是什么？计算资源与资助如何安排？ |
| 工作安排 | 实验室公开手册 | 到岗、假期、远程和实习怎样约定？是否因人／项目而异？ |
| 尊重与合作 | 公开署名和合作规则，只能提供部分事实 | 分歧怎样解决？署名怎样讨论？能否举最近的具体例子？ |
| 学生发展 | 校友页、个人主页、公开作品 | 去向信息是否完整？个人目标与组内支持是否匹配？ |

这组维度可参考 [CMU 博士指导原则](https://www.cs.cmu.edu/education/phd/doctoral-advising/values)中对明确预期、尊重、指导和合作的讨论；该原则不证明任何表中实验室实际符合。

后续若用户真正进入候选决策，再考虑分别了解两名在读学生和一名毕业生的经历，不要求现在发问卷。重点问具体事例和发生时间，避免只问“老师好不好”。[PI Review](https://pi-review.com/)等匿名经验站可提供待核实线索；评价覆盖、真实性、选择偏差和时间变化均限制结论，不能生成“人品分”。本次没有收集或传播具名负面指控。

个人比较页建议并列：研究兴趣、日常工作、指导与自主性、毕业和实习、申请条件、已知与待问事项。私人体验笔记不默认公开；导师介绍、本人宣传、学生经历要有不同标识。用待确认问题帮助决策，不用单一综合分替用户决定。

## 采集方案：先验证最有用的数据链

首个技术试验建议选五名导师的公开主页与论文入口，再试五个官方招生页；当前仅完成方案与网页阅读，尚未运行批量爬虫或验证采集成功率。

- 优先级一：稳定公开 HTML、PDF 和招生通知，提取必要摘要、链接、发布时间与适用年份；变更时更新字段，不重复生成候选。
- 优先级二：通过 [OpenAlex API](https://help.openalex.org/api/authentication/)及 [DBLP 开放查询服务](https://blog.dblp.org/2024/09/09/introducing-our-public-sparql-query-service/)补论文元数据；按当前接口规则设置认证与调用频率，不把元数据数量当研究质量。
- 优先级三：个人保存小红书／公众号等链接、文本或截图，辅助提取姓名、机构、研究主题和联系方式，再关联原始来源。尚未验证这些平台的稳定自动获取途径，不将登录可见内容假设为开放 API，也不绕过访问限制。
- 自动化顺序：先用人工整理样本确定字段，再实现一个公开站点适配器、去重与更新，观察真实维护耗时之后扩展。

数据组织须区分导师、课题组、研究主题／作品、招生机会、学位项目和个人笔记。一个人可能对应多个机构与机会；招生年度和查看日期是不同字段。机构变化、主页陈旧、跨站冲突和作者同名需保留待确认状态。

首轮试验记录：每条人工整理耗时、关键字段缺失、重复、过期及方向误判；验证是否帮助用户找到值得进一步了解的候选和明确下一步。不预设收集数量越大价值越高。

## 案例定位

本调研是产品工作流的样本输入。用户找导师用于验证路径，导师名单本身不是项目最终交付。现阶段各环节主要依靠人工浏览、整理和解释，尚无已实现的采集、比较或行动指导产品流程。复用目标及分工以[产品概览](../product/overview.md)为准。

## 下一步与尚缺信息

1. 先取少量现有样本跑通用户案例，记录各步输入、操作、输出、卡点和人工补位，形成可复走的流程说明。
2. 用另一组偏好（例如偏就业）走同一流程；模拟案例明确标注，检验是否只是针对本人名单定制。
3. 按流程实际暴露的信息缺口补近期作品、招生项目和比较内容；二十至三十条是扩样预算，不是先凑满才能验证流程。
4. 据此确定原型交互和采集试验，优先自动化重复且可核实的整理工作；小红书先作为发现与保存入口。

还未确定：用户目标入学年份、考虑的具体学位／地区优先级、已有研究与课程基础。它们影响申请筛选，但不妨碍当前方向探索。实验室实际培养体验依然待进一步了解。无需先发全校问卷。

### 内容判断与需求影响

依据方法，MPK可用“推理为何慢、计算通信怎样组织”解释工作；Clearblue可用“某个值怎样到达某处、什么条件导致缺陷”解释工作。实现、测量和误差分析等活动是研究者根据公开方法的推断，非在读学生经历，不表述为固定日常安排。两条都可先读问题与示例，不强制固定时长试做、硬件申请或代码复现；需要动手时再确定资源。

本轮作者对照检查：样稿能指出研究问题与方法差别，并保留招生／指导未知；无法得出用户偏好哪一条、就业适配、能力门槛或培养质量。两名候选仍仅覆盖香港／美国已有机构，未弥补国内跨校、研究所及其他学科样本缺口。

对N03/N04/N11的具体补充：保留“人物与作品的关联依据”“作品要解决的问题”“对工作内容的解释”和“当前参与机会”四者的区别。问题解释服务兴趣选择，技术术语仅保留能解释差异的部分；不将这套科研信息结构推广为所有活动的必填项。不新增导师排序或自动匹配评分，尚未完成真实使用验证。
